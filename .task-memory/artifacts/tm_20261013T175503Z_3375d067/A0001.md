## Final behavior

A new pure function, `projectOpenCodeExecutionEvent`, turns each of the four pinned `session.execution.*` frames for the owned session into an ordered, unmodifiable `List<SessionEvent>` of 0–3 events:

| Native frame | Execution state | Timeline item | Extra |
|---|---|---|---|
| `started` | kind `running`; `retryAt` and `error` cleared; prior `lastOutcome` kept | none | — |
| `succeeded` | kind `idle`; `lastOutcome = succeeded` | `TurnOutcome(succeeded)`, matching the history `idle` row | `ResyncRequired` when a tool is still unsettled |
| `failed` | kind `idle`; `lastOutcome = failed` with a sanitized `ErrorInfo` | `TurnOutcome(failed)` | same |
| `interrupted` with `user`, `superseded` or `inactivity` | kind `idle`; `lastOutcome = interrupted` with the reason | `TurnOutcome(interrupted)` | same |
| `interrupted` with `shutdown` | kind `interruptedPendingResume`; prior `lastOutcome` kept | **none** | **never** a resync |

**Unrelated types and foreign sessions.** Both return `const []`.

**Invalid frames.** Malformed, unsupported or over-limit frames throw `OpenCodeExecutionProjectionException(category)`. The exception never contains native content, and the whole frame is rejected at once.

**Why the shutdown row differs:**
- `session-message.ts:285-287` says a shutdown records no idle marker.
- The reference reducer returns before inserting a marker or refetching (`client-solid-data.reference-reducer.ts:1032`).
- The server keeps the execution claim "so the next server start resumes the turn" (`core/session_execution.ts:77-80,129-134`).
- The fixtures show it: C `provider-form-dismiss` and `provider-reject-none*` have a shutdown frame and no idle row with the matching ID. C `post-restart-question-recovery` then has a `succeeded` frame with no `started` before it, and it does have an idle row.

### 1. New file: `packages/harness_opencode/lib/src/execution_projection.dart`

**Failure type and exception.** Mirrors `tool_projection.dart:7-23`:
```dart

  final OpenCodeExecutionProjectionFailure failure;
  @override String toString() => 'OpenCodeExecutionProjectionException(${failure.name})';

```

**Signature:**
```dart
List<SessionEvent> projectOpenCodeExecutionEvent(
  Object? value,
  SessionState current, {
  required String sourceVersion,
  required StreamPosition position,
  required DateTime receivedAt,
});
```

**Validation order.** This copies the siblings (`tool_projection.dart:77-129`):
1. `frame` must be an object. `type` must be a String, else `malformed`. If `type` is not in the four-type set, return `const []`. Unknown future `session.execution.*` types are also ignored, as the siblings do.
2. `data` must be an object. `sessionID` must have the prefix `'ses'` (same prefix as the siblings, `tool_projection.dart:82`). If it is not `current.ref.nativeId`, return `const []`.
3. `OpenCodeCompatibility.parse(sourceVersion)?.toString() == '2.0.22'`, else `unsupportedVersion`. Then cap-check the host, harness, nativeId, `position.id` and `position.epoch` (4 KiB, non-empty).
4. `id` must have the prefix `evt_` and be at most 4 KiB. `created` must be a finite `num`.
5. `durable` is required for all four types, since all are durable (`session-event.ts:46-50,245-261`):
   - `aggregateID` has prefix `ses` and equals `sessionID`, else `malformed`;
   - `version` is a safe integer equal to 1, else `unsupportedVersion`;
   - `seq` is a safe non-negative integer, kept as a `BigInt`.
6. `failed` only:
   - `error` must be an object, and `error.type` a String of at most 4 KiB with valid UTF-16.
   - An empty type gives `unsupportedValue`. Core `ErrorInfo` needs a non-empty `rawType` (`errors.dart:29-35`), and the tool sibling does the same (`tool_projection.dart:175-178`).
   - `message`, `status` and `response` are **never read**. This follows the tool and history policy (README:219-221; `tool_projection.dart:182-186`).
7. `interrupted` only:
   - a non-String `reason` gives `malformed`;
   - a String that is not one of the four literals gives `unsupportedValue`.

**Error mapping.** `failed` becomes an `ErrorInfo` with `rawType` set to the error type, `rawMessage: ''`, `retryable: false`, and no `retryAt`, `action` or `details`. The `kind` comes from an exact table based on `core/session_to-session-error.ts:31-87`:

| Native type | `ErrorKind` |
|---|---|
| `provider.auth` | `auth` |
| `provider.rate-limit` | `rateLimit` |
| `provider.quota` | `quota` |
| `provider.content-filter` | `contentFilter` |
| `provider.transport`, `provider.timeout` | `network` |
| `permission.rejected` | `permissionRejected` |
| `tool.execution` | `toolFailure` |
| anything else, including `unknown`, `provider.internal`, `provider.no-route` and future types | `OpenValue.known(ErrorKind.unknown)` |

The table only classifies the error. It does not infer anything about retries.

**Shared source provenance.** Both events from one frame use the same `SourceProvenance`:
- `harness: current.ref.harnessRef`, `version: sourceVersion`, `nativeType: type`, `nativeEventId: id`, `aggregateId`, `aggregateSeq`;
- `durability: known(durable)`;
- `extra: CanonicalValue({'nativeCreated': created, 'nativeDurableVersion': 1, 'nativeMessageId': ?msgId (only when an outcome marker is derived), 'interruptReason': ?reason, if failed 'errorContentNotProjected': true})`.

`EventMeta` uses `owner: SessionOwner(current.ref)` plus the given `position` and `receivedAt`.

**Execution state.** Uses only existing Core types (`lifecycle.dart:36-58`):
- `started`: `ExecutionState(kind: known(running), lastOutcome: current.execution?.lastOutcome)`.
- terminal frames other than shutdown: `ExecutionState(kind: known(idle), lastOutcome: ExecutionOutcome(known(k), error: errorInfo?, reason: reason?))`. `ExecutionState.error` and `retryAt` are null; the failure error lives only on `lastOutcome`.
- shutdown: `ExecutionState(kind: known(interruptedPendingResume), lastOutcome: current.execution?.lastOutcome)`.

**TurnOutcome item** (terminal frames other than shutdown):
- `msgId = id.replaceFirst('evt_', 'msg_')`. This is the official `fromEvent` rule (`session-message.ts:27`, reference reducer line 76). The fixtures confirm it: 1/1 in A and every terminal in the B and D captures matched an idle row with the same outcome.
- `ItemId(jsonEncode([ref.storageKey, msgId, 'outcome', 0]))`, which equals the history ID (`history_projection.dart:200,515-523`).
- Generation follows the live sibling rule: `jsonEncode(['live', storageKey, msgId, position.id, position.epoch])` (`tool_projection.dart:192-198`).
- Status is `known(completed)`, ordinal is null, kind is `known(succeeded|failed|interrupted)`.
- `error` and `reason` are **null**, so a history row and a live item for the same marker stay identical. History cannot carry either field. The error and reason live on `ExecutionOutcome`.

**Resident check** for the outcome ID in `current.timeline`:
- a resident item that is not a `TurnOutcome` throws `itemKindMismatch`, as the siblings do;
- a resident `TurnOutcome` with the same known kind means the item is left out. The history or an earlier live row is not replaced or retired (`session_reducer.dart:664`);
- a resident `TurnOutcome` with any other kind gives `ResyncRequired(reason: 'executionOutcomeMismatch')`.

**Unsettled-tool trigger.** This mirrors the reference reducer at lines 1045-1054. For terminal frames other than shutdown: if `current.timeline` has any `ToolCall` whose `status.known` is `streaming` or `pending`, add `ResyncRequired(reason: 'executionToolUnsettled')`.

At most one `ResyncRequired` is emitted per frame, with `executionOutcomeMismatch` taking priority. This is required, not a style choice: `_observationKey` keys on the native ID, the runtime type and an empty target (`session_reducer.dart:1087-1110`), so a second `ResyncRequired` from the same frame would be dropped as a duplicate.

**Session-info revalidation.** The reference reducer's session-info revalidation is **not projected**. Doing it would mean a full `Rehydrate` on every terminal frame. It belongs to the stream owner, V2-042.

**Output order and helpers.** The result is `List.unmodifiable([ExecutionChanged, ItemUpserted?, ResyncRequired?])`, built only after every check has passed. The file gets private copies of `_object`, `_integer`, `_id`, `_text`, `_bytes` and `_fail` (pattern at `tool_projection.dart:423-485`), because refactoring a shared validator is out of scope.

## Edge cases
- **Terminal frame with no earlier `started`.** Accepted, with no dependence on state. Seen in B `service-restart` `newStream` (`succeeded` only) and C `post-restart-question-recovery`.
- **Empty revert wake drains** (D `revert-file-effects`, adjacent `started`/`succeeded` pairs). Each still produces a `TurnOutcome`, matching the 3 idle rows in the capture, and no assistant or provider item is invented (`opencode_v2_server.md` ~82-86).
- **Child sessions** (D `background-interrupt`, `foreground-nested`). Each frame is projected only against its own session state; foreign frames return `[]`. A parent going idle never changes a child.
- **Ordering.** Stale or duplicate frames are handled by Core:
  - a lower-seq `ExecutionChanged` loses at `acceptField` (`session_reducer.dart:216-219,551-558`);
  - the same native ID is deduplicated per event type and target, so `ExecutionChanged` and `ItemUpserted` from one frame never cancel each other;
  - a different epoch gives `Rehydrate(streamGenerationMismatch)`, which the caller handles.
- **Prior retrying state.** `started` clears `retryAt` and `error`. Terminal frames replace the state, so retrying ends.
- **`interrupted` with `superseded`.** It is in the schema, but the local server type omits it (`session_execution.ts:48`). Treat it like `user`.
- **Shutdown as the default interrupt reason.** The server uses `shutdown` whenever no explicit reason is given (`session_execution.ts:52`). The producer still trusts the wire literal.
- **Unknown extra fields in `data` or `error`.** Ignored and never read.

## Risks and mitigations
- **The `ErrorKind` table could be read as inference while retry/quota evidence is inconclusive (#243).** It only classifies the error, has no retry or action effects, keeps `rawType`, and is pinned to the source lines. Fallback: map every type to `ErrorKind.unknown`; this is a one-line change and the tests are parameterized.
- **`interruptedPendingResume` for shutdown assumes a resume.** The source states it at `session_execution.ts:77-80`, and C fixtures plus server doc ~66 show restart recovery. Fallback: use `ExecutionKind.unknown`, keeping the same "no marker" rule.
- **The tool-unsettled `ResyncRequired` causes a full `Rehydrate`, heavier than the reference's message refetch.** No observed capture triggers it; across all 27 capture streams with terminals, zero tools were open at a terminal frame. Fallback: drop the trigger and note it for V2-042.

## Final behavior

`projectOpenCodeExecutionEvent` is a synchronous, stateless function. The caller projects one native frame against the latest `SessionState`, then reduces every returned event before the next frame. Unrecognized types and foreign `sessionID`s return an empty list. A recognized in-session frame returns one or two canonical events, or throws a finite exception with no native text.

| Native frame | Canonical result |
|---|---|
| `session.execution.started` | One `ExecutionChanged`: `ExecutionKind.running`. `retryAt` and top-level `error` are null. `lastOutcome` is copied from `current.execution` so a full replace does not erase a prior completed outcome. |
| `session.execution.succeeded` | `ExecutionChanged` to `ExecutionKind.idle` with `lastOutcome` succeeded, then `ItemUpserted` of a completed `TurnOutcome`. |
| `session.execution.failed` | Same pair, outcome `failed`. `ErrorInfo` is on `ExecutionOutcome.error` only. |
| `session.execution.interrupted` with `user`, `superseded`, or `inactivity` | Same pair, outcome `interrupted`, reason literal on `ExecutionOutcome.reason` only. |
| `session.execution.interrupted` with `shutdown` | One `ExecutionChanged`: `ExecutionKind.interruptedPendingResume`. No timeline item. Prior `lastOutcome` is preserved, not replaced with interrupted. |

`retryAt` and top-level `error` are cleared on every emitted execution state. This unit does not project `session.retry.scheduled`.

The idle item matches history identity and completion, not history bookkeeping:

- ID: `ItemId(jsonEncode([current.ref.storageKey, messageId, 'outcome', 0]))`, the same formula as `history_projection.dart:200` and the idle case at `515-523`.
- `messageId` is `eventId.replaceFirst('evt_', 'msg_')`, the official `fromEvent` rule at `plan/opencode-v2-src/schema/session-message.ts:27`. Observed A confirms it: `evt_10527f123001Vvyi5SFyp2rYB6` is idle message `msg_10527f123001Vvyi5SFyp2rYB6` (`events.json:527-537`, `messages.json:122-127`).
- Status is `ItemStatus.completed` for succeeded, failed, and interrupted. History does not use `ItemStatus.failed` for an idle row.
- `TurnOutcome.kind` is the native outcome. `TurnOutcome.error` and `TurnOutcome.reason` stay null. The idle schema is only `{id, time, type, outcome}` (`session-message.ts:283-293`). Copying the failure onto the item would diverge from history and retain private text.
- Generation is the live formula `jsonEncode(['live', storageKey, messageId, position.id, position.epoch])`, not `['history', storageKey, messageId]`. A2/A3 already require that inequality (`text_reasoning_replay_test.dart:65-66`). History generations are adapter bookkeeping (`history_projection.dart:201`, package README). A later history hydration can replace the row because generations differ (`session_reducer.dart:852-855`).
- `ordinal` and `turnId` stay null. No turn or attempt is invented.
- Item `nativeType` is the execution event type, durability is `durable`, and provenance keeps `nativeCreated`, `nativeMessageId`, aggregate id/seq, and durable version `1`. History's idle row uses `nativeType: idle` and `Durability.unknown`. Parity is ID, status, and outcome kind, not provenance equality.

Shutdown is not idle. The server keeps the claim and does not record an idle message (`session_execution.ts:76-80`, `128-134`; `session-message.ts:283-286`). The reference client still sets its two-state flag to `"idle"` and then returns before inserting a marker (`client-solid-data.reference-reducer.ts:1025-1033`). CodeWalk already has `ExecutionKind.interruptedPendingResume` (`lifecycle.dart:25-34`, `v2-plan.md:759`). Use that kind and emit no `TurnOutcome`. Observed C `provider-form-dismiss.json:15694-15706` is a shutdown interrupt, and that file has no `"type": "idle"` row. This follows the server contract; it is not an ADR exception.

Both events share the caller `StreamPosition`. Core dedup includes runtime type and item id (`session_reducer.dart:1087-1110`), and `lastPosition` allows an equal seq (`202-204`). `acceptField` gates the execution collection only (`551-557`). Do not invent a second stream position.

Reduce `ExecutionChanged` first, then `ItemUpserted`, and do both before treating the frame as published.

Error policy for `failed`:

- Validate `error.type` (string, 4 KiB), `message` (string, 256 KiB), optional `status` (`int` 100..599), and optional `response.body` (string, 256 KiB). Then discard message, status, and body.
- `ErrorInfo.kind` is `ErrorKind.unknown`. `rawType` is the native type. `rawMessage` is `''`. `retryable` stays false. `details`, `action`, and `retryAt` stay null.
- Do not map `provider.auth`, `provider.quota`, or `provider.rate-limit` onto `ErrorKind`. The wire type is already the publisher classification (`session_to-session-error.ts:28-54`). Promoting it would imply recovery actions, and retry/quota evidence is still inconclusive.
- Empty `type` throws `unsupportedValue`, matching `tool_projection.dart:175-177`, because Core rejects an empty `rawType` (`errors.dart:36`).
- A nonempty unknown type is accepted and preserved. `Schema.String` is open (`session-error.ts:7-11`).
- Provenance may record only booleans: `errorMessageOmitted`, and `errorStatusOmitted` / `errorBodyOmitted` when those fields were present. Never store the values.
- Interrupt `reason` is one of the four schema literals (`session-event.ts:259`). It is selected contract data, not a message, and is stored on `ExecutionOutcome.reason`.

Reference-client refetches are not emitted. A tool still streaming at terminal, or session info being loaded, does not produce `ResyncRequired`. Those are client cache reads (`reference-reducer.ts:1046-1061`). This producer has no IO, and V2-042 owns hydration. A false `ResyncRequired` would also fire in tests whose `SessionState.info` is null. A resident item with the outcome ID that is not a `TurnOutcome` throws `itemKindMismatch` before any event is returned, so the frame is atomic. A resident `TurnOutcome`, including a history row, is replaced by a normal `ItemUpserted`; the reducer keeps the newer position.

Foreign and child sessions: return `[]` unless `data.sessionID == current.ref.nativeId`. A child frame is projected only when `current` is that child. Parent idle is not child completion (`opencode_v2_server.md:63`).

Durable rules: all four require `durable.version == 1`, `aggregateID == sessionID`, and a nonnegative integer `seq` within the safe integer range. Wrong version is `unsupportedVersion`. Missing or mismatched durable data is `malformed`. Aggregate sequence is provenance only. A gap is not loss (`opencode_v2_server.md:65`) and must not become `ResyncRequired`.

Version gate matches siblings: `OpenCodeCompatibility.parse(sourceVersion)?.toString() != '2.0.22'` fails `unsupportedVersion` only after the type and session match. `2.0.22+build` passes; prereleases do not (`version_policy.dart:10-34`).

Unrecognized types, including `session.retry.scheduled`, `session.status`, and `session.idle`, return `[]`. Location, metadata, and unselected data keys are not read or copied.

## Final behavior

A pure, synchronous, one-frame, state-aware producer `projectOpenCodeExecutionEvent` in `packages/harness_opencode` projects the four pinned durable OpenCode 2.0.22 execution events into canonical Core events. Caller projects then reduces each observation against the latest `SessionState` (project-then-reduce, mirroring siblings).

### Selected types and envelope

Accept exactly (pinned `plan/opencode-v2-src/schema/session-event.ts:242-261`):

- `session.execution.started` — `{sessionID}`
- `session.execution.succeeded` — `{sessionID}`
- `session.execution.failed` — `{sessionID, error: {type, message, status?, response?}}`
- `session.execution.interrupted` — `{sessionID, reason: "user"|"shutdown"|"superseded"|"inactivity"}`

All four use the shared durable options `aggregate: "sessionID", version: 1` (`session-event.ts:45-50` with `...options` spread at `:242-261`). Error shape is `SessionError.Error` (`plan/opencode-v2-src/schema/session-error.ts:7-12`): `type: String`, `message: String`, optional `status: Int 100..599`, optional `response: {body: String}`.

### Canonical mapping

**`started` → 1 event:**

- `ExecutionChanged(state: ExecutionState(kind: running, retryAt: null, error: null, lastOutcome: current.execution?.lastOutcome))`.
- Reference client sets session active `"running"` and inserts nothing else (`client-solid-data.reference-reducer.ts:1009-1011`). Preserving `lastOutcome` mirrors Core `RetryScheduled` preserving `lastOutcome` (`packages/codewalk_core/lib/src/reducer/session_reducer.dart:221-229`) and avoids inventing turn completion.
- `ExecutionChanged` is a level-set replace gated by `acceptField(SessionCollection.execution, position)` (`session_reducer.dart:216-220`).

**`succeeded` → 2 events, in this order:**

1. `ExecutionChanged(idle, lastOutcome: ExecutionOutcome(known succeeded))`, `retryAt: null`, `error: null`.
2. `ItemUpserted(TurnOutcome(kind: known succeeded, status: completed, error: null, reason: null))`.

**`failed` → 2 events, in this order:**

1. `ExecutionChanged(idle, lastOutcome: ExecutionOutcome(known failed, error: ErrorInfo), error: same ErrorInfo)`, `retryAt: null`.
2. `ItemUpserted(TurnOutcome(kind: known failed, status: completed, error: same ErrorInfo))`.

Error mapping (privacy-first, mirroring tool producer which copies only `rawType` and sets `rawMessage: ''`, `tool_projection.dart:172-187`):

- `kind: known(ErrorKind.unknown)` — no quota/rateLimit/contextOverflow inference; retry/quota native evidence is inconclusive per work-item constraints.
- `rawType`: native `error.type`, validated 4 KiB UTF-8, nonempty; empty → `unsupportedValue` (mirrors `tool_projection.dart:176-178`; Core `ErrorInfo` requires nonempty `rawType`, `packages/codewalk_core/lib/src/errors.dart:27-44`).
- `rawMessage: ''`. Native `message` is never copied.
- Native `status`/`response.body` are never copied. If present they are shape-validated (object/int-range check) but omitted — privacy policy per constraints; justification required if any future change copies them.
- `retryable: false`, `retryAt: null`, `action: null`, `details: null` — no retry inference (out of scope).

**`interrupted` → 1 or 2 events:**

- Always: `ExecutionChanged(idle, lastOutcome: ExecutionOutcome(known interrupted, reason: nativeReason), error: null)`, `retryAt: null`.
- If `reason != "shutdown"`, additionally: `ItemUpserted(TurnOutcome(kind: known interrupted, status: completed, reason: nativeReason))`.
- If `reason == "shutdown"`: **no** `TurnOutcome`. This mirrors the reference early return (`reference-reducer.ts:1033`: `if (... reason === "shutdown") return`) and the schema comment "A shutdown does not record one, since the resumed execution continues the same turn" (`plan/opencode-v2-src/schema/session-message.ts:283-287`), plus server-side claim preservation on shutdown vs release on deliberate stops (`plan/opencode-v2-src/core/session_execution.ts:119-147`, esp. `:128-136`).
- `reason` is the exact native literal (`user|shutdown|superseded|inactivity`); Core `ExecutionOutcome.reason` is `String?` (`packages/codewalk_core/lib/src/lifecycle.dart:38-43`) and `TurnOutcome.reason` is `String?` (`packages/codewalk_core/lib/src/timeline.dart:240-251`), so no enum coercion.

**Retry-marker clearing:** reference clears the active assistant retry marker on all three terminals (`reference-reducer.ts:1029-1032`). In Core this is subsumed by the level-set `ExecutionChanged(idle, ...)` replacing any `retrying` state set by `RetryScheduled`; no separate event is emitted. No `session.retry.scheduled` projection (explicitly out of scope).

**Refetch triggers are not projected.** Reference invalidates/refetches messages when assistant tool parts are still streaming/running at terminal, and revalidates session info when not loaded (`reference-reducer.ts:1046-1061`). The pure producer emits no refetch/resync for these: it must not inspect timeline tool states, invent hydration, or perform IO. Existing Core `Refetch`/`ResyncRequired` paths and the blocked V2-042 hydration parent own recovery.

**TurnOutcome identity (history parity):**

- History idle item: `id = jsonEncode([ref.storageKey, messageId, 'outcome', 0])`, `meta('outcome', 0, status: completed)` (`packages/harness_opencode/lib/src/history_projection.dart:199-210, 515-524`); history generations are `['history', storageKey, messageId]` (`history_projection.dart:201`).
- Live execution frames carry **no** `assistantMessageID` — only `sessionID` plus frame `id: evt_*`. Reference derives the idle message id via `evt_` → `msg_` (`reference-reducer.ts:76`, `messageIDFromEvent`; schema `fromEvent: evt_ → msg_`, `session-message.ts:27`; inserted at `reference-reducer.ts:1035-1045`).
- Live `TurnOutcome` therefore uses `msgId = nativeEventId.replace(/^evt_/, "msg_")` as the message component: `id = ItemId(jsonEncode([current.ref.storageKey, msgId, 'outcome', 0]))`, `status: completed`, `generation = jsonEncode(['live', storageKey, msgId, position.id, position.epoch])` (live-generation pattern mirrors `tool_projection.dart:192-198` and `text_reasoning_projection.dart:109-119`). IDs match history when the server persists the same `msg_`; generations deliberately differ so a live row never adopts a history/prior-epoch row (sibling policy: `tool_projection.dart:232-274`).
- **Unverified:** that every fixture terminal `evt_*` suffix equals the persisted history idle `msg_*` id. Verification step below compares A `events.json` terminal ids against `messages.json` idle id before freezing the parity assertion.

**Ordering and dedup:** when two events are returned they share the caller's `position` and are reduced in order `[ExecutionChanged, ItemUpserted]`. Core dedup key includes `runtimeType` (`session_reducer.dart:1087-1111`), so same-native-id pairs do not collide; `acceptField(execution)` and timeline `upsert` are independent collections.

**Ownership/provenance (mirrors siblings `tool_projection.dart:82-83`, `text_reasoning_projection.dart:60-62`):**

- Foreign `sessionID != current.ref.nativeId` → empty list (not an error; `/api/event` is global, cf. `ai-docs-for-opencode-v2/opencode_v2_server.md:59-63`).
- Unrelated `type` → empty list.
- Validate `frame.id: evt_` prefix, `created` finite num, `durable.aggregateID == sessionID`, `durable.version == 1`, `durable.seq` valid; caller identity strings (`host`, `harness`, `nativeId`, `position.id/epoch`) 4 KiB-checked (pattern at `tool_projection.dart:87-103`, `text_reasoning_projection.dart:67-81`).
- `SourceProvenance`: `harness: current.ref.harnessRef`, `version: sourceVersion`, `nativeType`, `nativeEventId`, `aggregateId`, `aggregateSeq`, `durability: known durable`, `extra: {nativeCreated, nativeDurableVersion}` only — no message/call ids (none exist), no error content, no turn/attempt inference.
- Child sessions: each event applies only to its own `sessionID`; parent idle never implies child completion (`opencode_v2_server.md:63`, `:71-78`). No lineage logic.

## Risks and mitigations

- **Two-events-one-frame vs sibling single-event shape:** callers looping `reduce` over a list could mis-order. Mitigate: return an already-ordered immutable list, document reduce-in-order, and keep the single-frame atomic validation inside one function rather than two independently callable functions that could diverge or double-validate.
- **History-parity id mismatch:** if fixtures show the persisted idle `msg_` differs from `evt_→msg_`, the live id would never match history. Mitigate: verification step 2 gates the parity assertion; fallback is live-scoped ids with parity asserted only where ids coincide, plus a test pinning the observed A mapping.
- **Privacy regression via error copying:** copying `message`/`status`/`body` would violate sibling policy. Mitigate: omit-by-construction (only `type` read), plus a negative test asserting absence and a README privacy note requiring justification for any future copy.
- **Shutdown outcome invented:** inserting a `TurnOutcome` on shutdown would fork the turn the restart continues. Mitigate: branch explicitly on `reason == "shutdown"` with a dedicated test.
- **Retry/quota misclassification:** mapping unknown failures to quota/rateLimit without evidence. Mitigate: fixed `ErrorKind.unknown`, no status-based inference, explicit out-of-scope note.
