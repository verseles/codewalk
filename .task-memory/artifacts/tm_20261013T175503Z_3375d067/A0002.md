### Final Behavior

A pure, synchronous, one-frame, state-aware projection module in `packages/harness_opencode`:
`projectOpenCodeExecutionLifecycleEvent(Object? value, SessionState current, {required String sourceVersion, required StreamPosition position, required DateTime receivedAt})`

Returns `List<SessionEvent>` (0, 1, or 2 events).

1. **Native Scope & Rejection**:
   - Accepts frames with `type` in:
     - `session.execution.started`
     - `session.execution.succeeded`
     - `session.execution.failed`
     - `session.execution.interrupted`
   - Unrelated event types return an empty list `const []`.
   - Requires verified 2.0.22 schema compatibility: `OpenCodeCompatibility.parse(sourceVersion)?.toString() == '2.0.22'`, failing with `OpenCodeExecutionProjectionException(unsupportedVersion)` otherwise.
   - Requires valid envelope framing:
     - Root object, valid `created` (non-negative integer <= 9007199254740991), native event `id` prefixed with `evt_` (non-empty, <= 4096 bytes).
     - Envelope `durable` block: `version == 1`, `aggregateID` matches `data.sessionID`, `seq` is an integer >= 1 and <= 9007199254740991. If missing, malformed, or version != 1, throws `OpenCodeExecutionProjectionException(malformed)`.
     - `data.sessionID` prefixed with `ses_` (<= 4096 bytes).
   - Foreign session filtering: If `data.sessionID != current.ref.nativeId`, returns `const []`.
   - Checks `current.ref` and `position` identity limits (non-empty, <= 4096 bytes) conforming to sibling bounds.

2. **Event Canonicalization & State Transitions**:
   - Every valid event produces an `ExecutionChanged` event carrying an updated `ExecutionState`:
     - **`session.execution.started`**:
       - `ExecutionState(kind: const OpenValue.known(ExecutionKind.running), retryAt: null, error: null, lastOutcome: current.execution?.lastOutcome)`.
       - Emits `[ExecutionChanged]`.
     - **`session.execution.succeeded`**:
       - `ExecutionState(kind: const OpenValue.known(ExecutionKind.idle), retryAt: null, error: null, lastOutcome: const ExecutionOutcome(OpenValue.known(ExecutionOutcomeKind.succeeded)))`.
       - Emits `[ExecutionChanged, ItemUpserted(TurnOutcome)]`.
     - **`session.execution.failed`**:
       - Validates `data.error` object:
         - `type`: String, non-empty, <= 4096 bytes.
         - `message`: String, <= 65536 bytes.
         - Optional `status`: Int in `100..599` if present; malformed if outside range or non-integer.
         - Optional `response.body`: String, <= 65536 bytes if present.
       - Sanitizes and categorizes into Core `ErrorInfo`:
         - `rawType`: sanitized `error.type` (or finite label if unexpected).
         - `rawMessage`: privacy-safe description; never copies arbitrary response bodies or unvetted provider raw text into logs/exception. The message is bounded and sanitized.
         - `kind`: mapped to known `ErrorKind` (e.g. `auth` for `provider.auth`, `rateLimit`, `quota`, `protocol`, or `unknown`).
       - `outcome = ExecutionOutcome(const OpenValue.known(ExecutionOutcomeKind.failed), error: errorInfo)`.

       - Emits `[ExecutionChanged, ItemUpserted(TurnOutcome)]`.
     - **`session.execution.interrupted`**:
       - Validates `data.reason` against Schema literals `["user", "shutdown", "superseded", "inactivity"]`. Any other value fails with `malformed`.
       - `outcome = ExecutionOutcome(const OpenValue.known(ExecutionOutcomeKind.interrupted), reason: reason)`.
       - `ExecutionState(kind: const OpenValue.known(ExecutionKind.idle), retryAt: null, error: null, lastOutcome: outcome)`.
       - Emits:
         - If `reason == "shutdown"`: Emits only `[ExecutionChanged]` (no `TurnOutcome` item is created; mirrors official schema & reference reducer invariant).
         - If `reason != "shutdown"` (`"user"`, `"superseded"`, `"inactivity"`): Emits `[ExecutionChanged, ItemUpserted(TurnOutcome)]`.

3. **TurnOutcome Parity with History Projection**:

A new pure producer in `packages/harness_opencode/lib/src/execution_projection.dart` maps one observed native frame to an **ordered list of canonical `SessionEvent`s** (empty = not ours):

| Native frame | Emitted events | `ExecutionState` | `TurnOutcome` item |
|---|---|---|---|
| `session.execution.started` | 1 × `ExecutionChanged` | `kind: running`, `retryAt: null`, `error: null`, `lastOutcome` **carried** from `current.execution?.lastOutcome` | — |
| `session.execution.succeeded` | `ExecutionChanged`, then `ItemUpserted` | `kind: idle`, `retryAt: null`, `error: null`, `lastOutcome: succeeded` | `kind: succeeded`, `status: completed`, `error: null`, `reason: null` |
| `session.execution.failed` | `ExecutionChanged`, then `ItemUpserted` | `kind: idle`, `retryAt: null`, `error: <ErrorInfo>`, `lastOutcome: failed` (same `ErrorInfo` instance) | `kind: failed`, `status: completed`, `error: <same ErrorInfo>`, `reason: null` |

### Answers to the six questions

**Q1 — API shape.** One function, `List<SessionEvent>`, ordered `[ExecutionChanged, ItemUpserted]`. A `SessionEvent?` cannot express a terminal frame that needs both the level-set execution change *and* the timeline marker, and splitting into two public functions pushes the "which ones do I call" burden onto the V2-042 caller, which is exactly the kind of silent-drop bug the Core dedup at `session_reducer.dart:1087-1111` makes hard to notice (the two events share a `nativeEventId` but differ by `runtimeType`, so they dedup independently — this is what makes the list safe). `ExecutionChanged` is returned first so that a caller bug which reduces only the first event still leaves the lifecycle correct. Rejected alternative: two functions returning `SessionEvent?` each; flip only if the judge wants strict sibling signature symmetry, at the cost of the caller contract above.

**Q2 — canonical mapping.** Table in *Final behavior*. `ExecutionChanged` is a level-set replace (`session_reducer.dart:216-220`), so every field is explicitly chosen each time: `retryAt` is always `null` (this producer never schedules retries, and a live observation is newer than any hydrated snapshot, so a stale `retryAt` must not survive); `lastOutcome` is **carried** on `started` following Core's own precedent for preserving it across a phase change (`session_reducer.dart:227`) and set fresh on every terminal.

Rejected alternative: map `shutdown` to `ExecutionKind.interruptedPendingResume` (`lifecycle.dart:33`, otherwise unused in Core). The pinned reference client maps *every* terminal to `"idle"` (reference reducer `:1028`), and narrowing the kind for one reason is a CodeWalk product refinement, not a contract fact. The distinction is preserved losslessly as `lastOutcome.reason == 'shutdown'`, which is the slot Core provides (`lifecycle.dart:41`). Flip if the judge prefers the narrower kind — it is a one-line change plus one test.

`TurnOutcome.reason` is always `null`: the authoritative history `idle` message carries only `outcome` (`session-message.ts:289-293`) and the history producer emits no reason (`history_projection.dart:515-524`), so putting the reason in the item would create a live-only field that hydration silently downgrades. The reason lives in `ExecutionOutcome.reason`.

**Q3 — error mapping for `failed`.**

```dart
ErrorInfo(
  kind: const OpenValue.known(ErrorKind.unknown),
  rawType: errorType,     // bounded 4 KiB, nonempty  rawMessage: '',         // native message never read
)
```

`ErrorKind.unknown` because the four-event pin gives only a free-form `type: String` (`plan/opencode-v2-src/schema/session-error.ts:7-12`) with no verified mapping table to `ErrorKind.quota`/`rateLimit`/`network`/… in the fixtures, and retry/quota native evidence is explicitly inconclusive (#243). Guessing a kind would manufacture classification the contract does not support; `unknown` is the canonical safe value and Core already models it (`errors.dart:14`). `rawType` retention is the established sibling policy (`tool_projection.dart:174-186`), bounded to 4 KiB and required nonempty. `message`, `status` and `response.body` are **never read** — enforced structurally by the test-side `PrivateExecutionFields`, exactly as `tool_projection_test.dart:466-533` does for tool errors, and recorded as `'errorDetailsNotProjected': true` in provenance.

**Q4 — the reference client's refetch triggers.** Neither trigger is actioned; both are recorded or deferred.

- *Tool parts still streaming/running at terminal* (reference reducer `:1046-1057`): pure and state-observable, so the producer scans `current.timeline` for a `ToolCall` with `status.known == ItemStatus.streaming` at a terminal frame and sets `'residentToolPartOpen': true`. It does **not** emit `ResyncRequired`. Rationale: the reference invalidates because its store is read-sync'd and an event can overtake an in-flight first read — a race/revalidation concern owned by the blocked V2-042 subscription/hydration parent, and explicitly out of scope here ("no subscription/hydration/reconnect handling"). Emitting `ResyncRequired` would also discard the authoritative terminal marker, which the reference keeps. Flagging it keeps the evidence observable and testable without inventing recovery. Flip condition: if the A/B/D replay shows this flag firing on an ordinary capture, the guard is wrong and should be removed before merge (see Risks).
- *Session info not loaded* (reference reducer `:1058-1061`): pure client-cache concern, no native field to observe. Not represented at all.

**Q5 — ownership/provenance.** Foreign `sessionID` → empty list (step 4). Child sessions are therefore invisible to the parent's state — the "parent idle does not prove child completion" rule (`ai-docs-for-opencode-v2/opencode_v2_server.md:63`) holds structurally, and each child reducer owns its own events. `durable.version != 1` → `unsupportedVersion`; `aggregateID != sessionID` or missing/negative/fractional/huge `seq` → `malformed`. Native event ID must match `evt_` (`_id(frame['id'], 'evt_')`), the same rule as both siblings. Ordering against Core `acceptField` needs no producer logic: `ExecutionChanged` is gated by `session_reducer.dart:217` and `ItemUpserted` by `upsert()` (`:632-682`), which are independent collections, so both events at the same position are accepted; re-observation at the same position is dropped by `_observationKey` (`session_reducer.dart:1087-1111`) and by `acceptField`'s `_atLeast` check (`:551-558`). The producer never fabricates or reorders positions.

**Q6 — tests.** Specified in full under *Tests and validation*.

## Edge cases

1. **Empty revert wake drain** — `started`/`succeeded` 4 ms apart with no assistant content still emits a `TurnOutcome` (`d/revert-file-effects.json:18738-18762` ↔ history `:17305-17311`). The producer must not suppress "contentless" executions; the contract gives it no such rule and the anchor forbids treating a start as a new provider message (`opencode_v2_server.md:82-85`).
2. **Interrupt then immediate resume** — `interrupted(user)` at seq 14 immediately followed by `started` at seq 15 (`b/interrupt-resume.json:921-944`). The new `started` carries `lastOutcome: interrupted` rather than clearing it.
3. **Shutdown interrupt** — emits only `ExecutionChanged`; no item, no `ItemsRemoved`, and no attempt to remove or alter any pre-existing item (`session-message.ts:283-286`).
4. **Repeated terminal at the same position** — dropped by Core dedup; at a newer position it level-replaces with identical content. Assert `reduce(state, events[i]).state` is `same(state)` on the second pass, mirroring `tool_replay_test.dart:143-148`.
5. **Terminal with no prior `started`** — still projected. The native server emits one terminal per busy period (`core/session_execution.ts:118` "One terminal observation per busy period, covering every coalesced drain"), so a terminal without a locally observed start is a legitimate observation (missed prefix, or an execution begun before subscription). Unlike the tool producer's `toolStartMissing` (`tool_projection.dart:272-274`), a missing execution start is **not** a `ResyncRequired`: the terminal is self-sufficient and the contract states no prerequisite.
6. **`superseded` / `inactivity`** — schema-valid but never emitted by the pinned server: `superseded` appears only in `session-event.ts:259` and `client-generated-types.ts:691`, never in `core/session_execution.ts` (whose `InterruptReason` is `"user" | "shutdown" | "inactivity"`, line 48); no fixture contains either. Accepted, mapped identically to `user` except for the recorded reason; covered by source-shaped tests labelled as unobserved.
7. **Empty `error.type`** — schema permits `Schema.String` (so empty is valid upstream), Core forbids it (`errors.dart:36`) → `unsupportedValue` (`tool_projection.dart:174-178`).
8. **Session running with no terminal across a disconnect** — `b/disconnect-reconnect.json` `partialStream` contains `execution.started` (`:1184`) while `completionWhileDisconnectedObserved` is `true` (`:1574`); `reconnectedStream` holds only `server.connected`/`session.renamed`. Execution correctly stays `running` with `lastOutcome: null`. The producer must never synthesize a terminal — `ADR.md:3808` forbids inferring execution completion from a disconnect.
9. **Foreign/child session frame in the same stream** — empty list, no exception, no effect on the resident state. Covered by D parent/child captures (`d/foreground-nested.json`).
10. **`created` as an int, double or negative double** — accepted as a finite `num` and retained verbatim, matching `tool_projection.dart:100-103, 212`.
11. **`durable.version` = 2** — `unsupportedVersion`, not `malformed` (`tool_projection.dart:124-127`).

## Risks and mitigations

1. **Multiple emitters per frame is a new pattern in this package.** No sibling needs it. Mitigation: document the caller contract in the dartdoc ("reduce every returned event in order, each against the latest state"), assert the reduction order explicitly in tests 1 and 6, and pin the two-event dedup independence (`session_reducer.dart:1110`) so a future single-event refactor breaks a test rather than silently dropping the marker.
2. **The `residentToolPartOpen` guard may be wrong about native ordering.** If the native server ever emits an execution terminal while a tool part is still streaming, the flag would fire on ordinary captures and the Q4 decision would need revisiting. Mitigation: tests 17-21 assert the flag is **absent** across the immutable A/B/D replays; if any fires, drop the guard before merge rather than relaxing the assertion. *(Unverified whether the three `fledge-policy-denial` failures — `b/queue-steer-fledge-policy-denial.json:1057,1285,1405` — have an open tool; that capture reports `toolCalledObserved: false` at `:1503`, which suggests not.)*
3. **Divergence from the tool producer's `ResyncRequired` on resident items** (Q5). Mitigation: the rationale is recorded in the dartdoc and the behaviour is pinned by test 8; the reviewer can require `ResyncRequired` with a one-line change if it prefers strict sibling symmetry.
4. **`ErrorKind.unknown` may look under-specified.** Mitigation: test 4 pins it, and the plan states that any promotion to a specific kind requires the same verified mapping the retry/quota evidence is still waiting on (#243).
5. **Hardcoding fixture IDs.** Mitigation: tests 17-21 derive expectations from the fixture frames; only the A `msg_…` value is asserted literally, because that string is the point of the test and it is confirmed in `events.sse:53` ↔ `messages.json:122`.
6. **Documentation drift.** The package README, `CODEBASE.md` and `BEHAVIOR.md` will be stale after this lands. Mitigation: flag them for the orchestrator's documentation pass (README section after line 240, `CODEBASE.md` section after line 1664, mirroring the A2/A3 entries at `CODEBASE.md:1613-1642` and `1644-1664`). Not part of this unit's code change.
7. **G4 1,500-line cap** (`ADR.md:3814`). Mitigation: producer target ≤ 350 lines, test files ≤ 500 each.

## Assumptions with verification and fallback

1. **Both events from one frame reduce successfully.** Basis: independent collections (`SessionCollection.execution` vs `timeline`) in `session_reducer.dart:216-220` and `:632-682`, plus type-distinct `_observationKey` (`:1110`). Verification: test 1 reduces both and asserts both took effect. Fallback: if a same-position conflict appears, return `[ItemUpserted, ExecutionChanged]` — the order is not load-bearing for correctness.
2. **`SessionState.timeline` is the right place to detect an open tool part.** Basis: tool items live in the timeline (`timeline.dart:189`, `session_reducer.dart:206-211`). Verification: test 16. Fallback: drop the flag entirely; no other behavior depends on it.
3. **`d/*.json` and `c/*.json` are readable by the new test** via `OpenCodeFixtures().root` (`fixture_replay.dart:55, 190-203`). Basis: `root` is public and the A/B tests already build paths from it (`tool_replay_test.dart:41-43`). Verification: test 20's first run. Fallback: restrict the D/C cases and note the gap.
4. **History/live ID convergence for the `idle` marker.** Basis: `session-message.ts:27` + reference reducer `:76`, plus four independent fixture confirmations listed in *Final behavior*. Verification: test 17 asserts it end to end. Fallback: none needed — this is directly evidenced, not assumed.
5. **No ADR exception is required.** Basis: the mapping reproduces the pinned reference reducer's observable behavior exactly (`:1009-1060`) and the schema's `Idle` note; the only divergence (no refetch) is Core-architecture-shaped, not contract-shaped, and `ADR-023:3` (`ADR.md:1124`) governs *semantic* divergence from official server semantics. Verification: reviewer confirms against `ADR.md:1110-1126`. Fallback: if judged a divergence, file an ADR exception with rationale, risk, rollback and tests as `ADR.md:1124` requires.
6. **Test 22 (`c/` capture) is in scope.** Basis: `c/provider-reject-none.json` is the only immutable `shutdown` evidence, and the objective names shutdown explicitly. Fallback: drop test 22 and cover shutdown solely with the source-shaped test 6 — the mapping evidence is unchanged.
