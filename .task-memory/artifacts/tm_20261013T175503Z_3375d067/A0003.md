## Final Behavior

Unit V2-044A4 adds a pure, synchronous, one-frame, state-aware production producer in `packages/harness_opencode` that projects OpenCode 2.0.22 execution lifecycle events into canonical Core session events.

### 1. Function Contract and Signature

```dart
List<SessionEvent> projectOpenCodeExecutionEvent(
  Object? value,
  SessionState current, {
  required String sourceVersion,
  required StreamPosition position,
  required DateTime receivedAt,
});
```

- **Pure & Synchronous:** No clock queries, no I/O, no network or async streams, no retained mutable state.
- **Unrelated / Foreign Frames:** Returns `const []` when `frame['type']` is not in the recognized set `{'session.execution.started', 'session.execution.succeeded', 'session.execution.failed', 'session.execution.interrupted'}` or when `frame['data']['sessionID'] != current.ref.nativeId`. Global SSE frames for other sessions are dropped silently without mutating or failing.
- **Malformed / Incompatible Frames:** Throws `OpenCodeExecutionProjectionException(failure)` with sanitized categories; never includes native payload fragments or identifiers in exception text.

### 2. Multi-Event Emission and Reducer Composition

OpenCode emits 1 native SSE frame at terminal execution that carries both the session execution state transition to idle and turn completion. In Core:
- Session execution state is tracked in `SessionState.execution` (`SessionCollection.execution`) updated via `ExecutionChanged`.
- Turn outcomes are tracked in `SessionState.timeline` (`SessionCollection.timeline`) updated via `ItemUpserted` with a `TurnOutcome`.

`projectOpenCodeExecutionEvent` returns an unmodifiable `List<SessionEvent>`:
- **`session.execution.started`**: Emits `[ExecutionChanged]` (1 event).
- **`session.execution.succeeded`**: Emits `[ExecutionChanged, ItemUpserted]` (2 events).
- **`session.execution.failed`**: Emits `[ExecutionChanged, ItemUpserted]` (2 events).
- **`session.execution.interrupted` (`reason != 'shutdown'`)**: Emits `[ExecutionChanged, ItemUpserted]` (2 events).
- **`session.execution.interrupted` (`reason == 'shutdown'`)**: Emits `[ExecutionChanged]` (1 event).
- **Unrelated types / foreign sessions**: Emits `const []` (0 events).

**Reducer Composition & Ordering:**
- In Core's `session_reducer.dart` (`reduce(SessionState, SessionEvent)`), `ExecutionChanged` targets `draft.acceptField(SessionCollection.execution, position)` and `ItemUpserted` targets `draft.acceptField(SessionCollection.timeline, position)`. Because `execution` and `timeline` are distinct collections, both events succeed at the same stream position without causal barrier collisions (`session_reducer.dart:217, 551, 793`).
- In `_observationKey(event)` (`session_reducer.dart:1087-1111`), `ExecutionChanged` produces `["native", nativeId, "ExecutionChanged", ""]` while `ItemUpserted` produces `["native", nativeId, "ItemUpserted", "[\"item\", ...]"]`. Their observation keys are distinct, so reducing both does not trigger duplicate observation deduplication.
- Order in the list is always `ExecutionChanged` first, then `ItemUpserted`. This matches the official reference client (`plan/opencode-v2-src/client-solid-data.reference-reducer.ts:1028-1035`) which transitions session state to idle before inserting the idle message.

### 3. Canonical Event Mappings

All execution events in OpenCode 2.0.22 are durable (`session-event.ts:45-50` with aggregate `"sessionID"` and version 1).
Common `EventMeta` and `SourceProvenance`:
- `EventMeta`: `owner: SessionOwner(current.ref)`, `position: position`, `receivedAt: receivedAt`.
- `SourceProvenance`: `harness: current.ref.harnessRef`, `version: sourceVersion`, `nativeType: type`, `nativeEventId: nativeId`, `aggregateId: aggregateId`, `aggregateSeq: aggregateSeq`, `durability: OpenValue.known(Durability.durable)`, `extra: CanonicalValue({'nativeCreated': created, 'nativeMessageId': nativeMessageId, 'nativeDurableVersion': 1})`.

#### A. `session.execution.started`
- **Native Frame:** `data: { sessionID }`.
- **`ExecutionState`:**
  - `kind`: `const OpenValue.known(ExecutionKind.running)`.
  - `retryAt`: `null`.
  - `error`: `null`.
  - `lastOutcome`: `null` (turn is running; prior turn's outcome is cleared, matching `synthetic_reducer_test.dart:596, 703`).
- **Timeline Item:** None. Resumed/started execution produces no timeline item directly.

#### B. `session.execution.succeeded`
- **Native Frame:** `data: { sessionID }`.
- **`ExecutionState`:**
  - `kind`: `const OpenValue.known(ExecutionKind.idle)`.
  - `retryAt`: `null`.
  - `error`: `null`.
  - `lastOutcome`: `const ExecutionOutcome(OpenValue.known(ExecutionOutcomeKind.succeeded))`.
- **`TurnOutcome` (via `ItemUpserted`):**
  - `id`: `ItemId(jsonEncode([current.ref.storageKey, nativeMessageId, 'outcome', 0]))` where `nativeMessageId = nativeId.replaceFirst(RegExp(r'^evt_'), 'msg_')` (`reference-reducer.ts:76`). This achieves exact 1:1 ID parity with `history_projection.dart:200, 518`.
  - `generation`: `jsonEncode(['live', current.ref.storageKey, nativeMessageId, position.id, position.epoch])` (matching sibling live generation schema).
  - `status`: `const OpenValue.known(ItemStatus.completed)`.
  - `ordinal`: `null`.
  - `kind`: `const OpenValue.known(OutcomeKind.succeeded)`.
  - `error`: `null`.
  - `reason`: `null`.

#### C. `session.execution.failed`
- **Native Frame:** `data: { sessionID, error: { type: String, message: String, status?: Int, response?: { body: String } } }`.
- **Error Mapping & Privacy:**
  - `error['type']` is validated non-empty string capped at 4096 bytes (`_idLimit`). If empty, fails closed with `unsupportedValue`.
  - `ErrorInfo.rawType`: exact string from `error['type']`.
  - `ErrorInfo.rawMessage`: `''` (strictly empty string, mirroring `tool_projection.dart:185` and `history_projection.dart:438`).
  - Privacy policy: Native `error['message']`, `error['status']`, and `error['response']['body']` are never copied into `rawMessage`, `details`, or `extra`. Native error bodies frequently contain provider tokens, raw server file paths, prompt fragments, and internal messages (`queue-steer-fledge-policy-denial.json: provider.auth with console body`).
  - `ErrorInfo.kind`: mapped deterministically based on `type` prefix/tag:
    - `'provider.auth'` $\to$ `ErrorKind.auth`
    - `'provider.quota'` $\to$ `ErrorKind.quota`
    - `'provider.rate-limit'` $\to$ `ErrorKind.rateLimit`
    - `'provider.content-filter'` $\to$ `ErrorKind.contentFilter`
    - `'provider.transport'`, `'provider.timeout'` $\to$ `ErrorKind.network`
    - `'permission.rejected'` $\to$ `ErrorKind.permissionRejected`
    - `'tool.execution'` $\to$ `ErrorKind.toolFailure`
    - Any other or unmapped type $\to$ `ErrorKind.unknown`.
- **`ExecutionState`:**
  - `kind`: `const OpenValue.known(ExecutionKind.idle)`.
  - `retryAt`: `null`.
  - `error`: projected `ErrorInfo`.
  - `lastOutcome`: `ExecutionOutcome(const OpenValue.known(ExecutionOutcomeKind.failed), error: error)`.
- **`TurnOutcome` (via `ItemUpserted`):**
  - `kind`: `const OpenValue.known(OutcomeKind.failed)`.
  - `error`: projected `ErrorInfo`.
  - `reason`: `null`.
  - Same `ItemId`, `generation`, `status: completed` structure as succeeded.

#### D. `session.execution.interrupted`
- **Native Frame:** `data: { sessionID, reason: "user" | "shutdown" | "superseded" | "inactivity" }`.
- **Reason Validation:** Must match one of the 4 official schema literals (`session-event.ts:259`). Any other string fails with `unsupportedValue`.
- **`ExecutionState`:**
  - `kind`: `const OpenValue.known(ExecutionKind.idle)`.
  - `retryAt`: `null`.
  - `error`: `null`.
  - `lastOutcome`: `ExecutionOutcome(const OpenValue.known(ExecutionOutcomeKind.interrupted), reason: reason)`.
- **Timeline Item Handling:**
  - **If `reason == 'shutdown'`:**
    - Per `session-message.ts:285-286` and `reference-reducer.ts:1033`: "A shutdown does not record one, since the resumed execution continues the same turn."
    - No `TurnOutcome` is generated. Returns only `[ExecutionChanged]`.
  - **If `reason != 'shutdown'` (`'user'`, `'superseded'`, `'inactivity'`):**
    - The turn has completed with interruption.
    - Emits `TurnOutcome` via `ItemUpserted` with `kind: const OpenValue.known(OutcomeKind.interrupted)`, `reason: reason`, `error: null`. Returns `[ExecutionChanged, ItemUpserted]`.

### 4. Reference Client Refetch Triggers Evaluation

In `plan/opencode-v2-src/client-solid-data.reference-reducer.ts:1046-1062`, when execution ends, Solid-level triggers check:
1. If any assistant tool part is still streaming/running, it calls `sync.invalidate("session.message:...")`.
2. If `store.session.info` is not yet loaded, it calls `result.session.invalidate(...)`.

In CodeWalk's architecture:

## Edge Cases

1. **Empty Revert Wake Drains:**
   - Official server doc (`ai-docs-for-opencode-v2/opencode_v2_server.md:76-86`) indicates reverting clear calls `execution.wake` and produces empty execution start/success drains without any assistant messages.
   - *Behavior*: `session.execution.started` sets `execution.kind: running`, then `session.execution.succeeded` sets `execution.kind: idle` and records a `TurnOutcome`. No timeline content is assumed, and no assistant text or tool item is required.
2. **Repeated `started` Events:**
   - If consecutive `started` events arrive (e.g. from upstream reconnect or wake drains), each emits `ExecutionChanged(kind: running, lastOutcome: null)`. In Core, `draft.acceptField(SessionCollection.execution, position)` handles monotonic sequence level-sets idempotently without error.
3. **`shutdown` Interruption vs User/Inactivity/Superseded Interruption:**
   - `shutdown` sets `ExecutionState.kind: idle` and `lastOutcome.reason: 'shutdown'`, but emits **no** `TurnOutcome`.
   - User, inactivity, and superseded interruptions set `ExecutionState.kind: idle` and emit `TurnOutcome` with the corresponding reason.
4. **Empty Error Type (`""`):**
   - Core's `ErrorInfo` constructor requires `rawType = requireText(rawType, 'rawType')` (must be non-empty, `errors.dart:36`).
   - If native `error['type']` is empty, the projector rejects it atomically with `OpenCodeExecutionProjectionFailure.unsupportedValue` instead of letting an unhandled `ArgumentError` escape.
5. **Unknown / Unrecognized Error Types:**
   - If an unexpected error type arrives (e.g. from an engine extension), it is mapped to `ErrorKind.unknown`, but `rawType` preserves the sanitized identifier (capped at 4096 bytes).
6. **Foreign Session IDs in SSE:**
   - `/api/event` is global. Events where `data['sessionID'] != current.ref.nativeId` return `const []` immediately without parsing durable fields or raising errors (`text_reasoning_projection.dart:61`).
7. **ID Generation Parity:**
   - Deriving message ID via `nativeId.replaceFirst(RegExp(r'^evt_'), 'msg_')` produces the exact `msg_` ID that `history_projection.dart` parses from `/api/session/{id}/message`. Replaying history over live state or vice versa results in identical `ItemId`, avoiding duplicate outcome items.

## Risks and Mitigations

## Risks and mitigations

- Error type strings can be unfamiliar or future values. Keep the raw type bounded, map only exact recognized values, and use `unknown` otherwise.
- Omitted message/status/body means the timeline does not carry native failure text. This matches the sibling projection’s privacy policy and keeps the failure detail in the sanitized execution outcome (`packages/harness_opencode/README.md:218-226`).
- Shutdown deliberately produces no idle timeline row, so history and live state temporarily lack an outcome marker until resumed execution settles. Preserve the shutdown reason in execution state; do not invent a turn boundary.
- Local B/D captures inspected show user interruptions; they do not show `shutdown`, `superseded`, or `inactivity` literal reasons. Cover those with schema-shaped unit cases. The B service-restart capture still covers resumed lifecycle behavior (`test/contract/fixtures/opencode/2.0.22/b/service-restart.json:1341,1977`).
