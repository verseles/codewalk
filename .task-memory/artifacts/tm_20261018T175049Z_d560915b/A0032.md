ACCEPTED (applied in the fix round 2):
R2-W1 (Space-bunny, DeepSeek) - the committed fixture named a commit that could not have produced it: the run was made from a dirty tree and the artifact in the repository belonged to an earlier run. Fix: the launcher records repoCommit and repoTreeDirty at the start of the run, the fixture refuses to be written from a dirty tree, and the fixture is regenerated from the clean committed tree.
R2-W2 (Space-bunny) - the egress counter counted observed sockets, not audit invocations, so it could not support the README claim that the host was sampled while the suite ran. Fix: the auditor records auditRuns, socketsObserved, firstAuditAt and lastAuditAt; the validator gates on auditRuns >= 2.
R2-S1 (Space-bunny, DeepSeek) - the secret guard ran after the files were written, so a detected leak stayed on disk and in a committable path. Fix: the evidence bundle, the log tails, the markers and every fixture file are scanned before they are written, and the pattern now covers an Authorization header, a bearer value, a Basic header and a credential field.
R2-S2 (Space-bunny) - the status came from the flutter exit code alone: a missing capability or an unproven zero-spend claim still reported a delivery. Fix: the run fails when a capability is not passed or when the zero-spend claim does not hold.
R2-S3 (Space-bunny) - a missing native-cost observation was published as a measured zero. Fix: _native_cost returns None without the marker, the zero-spend claim then does not hold and the run fails.
R2-S4 (Space-bunny) - only Fatal was caught: a timeout or a failed setup step left the evidence inconclusive with no reason. Fix: any other exception is caught, recorded as failed with its type and message.
R2-S5 (Space-bunny) - the hold counter did not say whether it counted a client disconnect or the deadline. Fix: the stub records the end reason; the fixture publishes holdEnds, holdAbortedByDisconnect and holdTimedOut, and the validator requires the disconnect.
R2-S6 (Space-bunny, Grok, DeepSeek) - the documentation stated 39 validator checks while the validator produced 40, and the README misdescribed which files are generated. Fix: the count was removed from the prose and the README now says that only the README and validate.py are not launcher-generated, and that validation.json is derived by the validator.
R2-S7 (Space-bunny) - the live-suite child inherited the user's credential-shaped environment and its output is captured into the evidence bundle. Fix: _child_env drops the proxy variables and the credential-shaped variables, keeping only the disposable password the launcher owns.
R2-S8 (DeepSeek) - the cleanup dict still carried the obsolete user_opencode_processes_unchanged key, which read false forever. Fix: the key is gone; the before/after process sets are recorded as observations.
R2-S9 (DeepSeek) - the user_listening_ports_preserved gate compared the whole host listener set, so a user action during the run failed the run as if it were a leak. Fix: the removed ports are recorded as an observation and the gate is limited to what the run owns: its process group, its ports, its tree, and the user's OpenCode service still alive.
