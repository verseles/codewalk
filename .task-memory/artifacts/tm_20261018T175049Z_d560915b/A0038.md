V2-043C review round 1, batch 2 of 2 (Muse-spark, Gemini-38, Claude-opus-5-xhigh-F).

All three delivered a schema-valid report with the same verdict: fix_required, overall_risk medium, confidence high. They confirm the batch-1 findings and add the ones below. The orchestrator verified each against the code.

I. The profile switch leaks transport state. _closeChanges resets `behind` but leaves `_liveConnected` untouched, so a newly selected profile whose feed is not connected skips the "behind" mark, and a pending acquisition is not retired: the lease of a profile that is gone can still be created. Fix: the acquisition is bound to a token that _closeChanges increments, and _closeChanges resets the connection state.

II. A manual "load more" always schedules a full head-to-depth re-read, even when no automatic read was in flight, which doubles the paging traffic. Fix: the manual page only supersedes an automatic read that is actually pending or running.

III. At the row or page limit the automatic re-read leaves `hasMore` true while `limited` is true, so the Load more control stays enabled and no-ops; the manual read masks it. Fix: derive `limited` as the manual read does and mask `hasMore` with it; a successful automatic read also clears the stale flag and the catalog failure.

IV. The expanded row keeps the pre-read summary, so a session renamed elsewhere keeps its old title. Fix: the expanded row is resolved against the rows the server just returned.

V. The credential fence in the live directory only counted the live handles, so a credential change while a catalog lease holds the profile closed the slot instead of refusing the second secret. Fix: the fence counts the catalog leases too, exactly like the catalog's own path.

VI. The automatic re-read kept using a credential the client already considers expired and ran while the host list was reloading, and an authentication failure was handled as a generic failure instead of the manual path. Fix: the automatic read passes the same fence as a manual one, and an authentication failure clears the list and releases the feed exactly like the manual read.

VII. The feed that ends (a closed slot, a terminal stream) left the catalog pull-only without a notice. Fix: the end of the feed marks the list behind and releases the feed, so the next successful read acquires a new one.

VIII. The unit's lint suppression was the only `// ignore` under lib/features; the orchestrator removed it by cancelling the subscription field directly, and the analyzer is clean without it.

Accepted tradeoffs recorded: the catalog keeps the profile's stream open even with no live session (a direct consequence of the one-stream decision); a child session's creation also triggers a bounded re-read; the re-read re-walks up to ten pages instead of patching a row; any successful manual read lifts the automatic suspension; the existing liveStale string is reused.

Non-issues recorded: one stream per endpoint holds (the lease only listens to the owner, the directory reuses the slot, the test asserts a single event request); the extraction is mechanical; the signal carries only the kind and is emitted before every filter, and the buffered frames arrive only after the release, so events during the hydration still reach the list; session.renamed exists in the recorded 2.0.22 fixtures; the native cursor is opaque and keyset, so a traversal tends to omit rows rather than duplicate them; the architecture guard holds; the dispose path cancels the timer and closes the feed.
