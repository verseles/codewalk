V2-043D planning, batch 1 of 2: DeepSeek, Grok, Space-bunny. All three delivered a full plan and converge on the same decision.

The consensus decision: the group key is the ProjectRef identity (the endpoint host plus the server-reported canonical directory), and the server's projectID stays only as the upstreamProjectId annotation.
- The projection already reads the server's location.directory (it keeps it in the metadata as nativeDirectory) and the server's projectID (nativeProjectId); the change is to carry them into SessionInfo.project as ProjectRef(host, directory, upstreamProjectId: projectID) and to stop treating the metadata copy as the only record of them.
- The key is deliberately not the native projectID: a Git directory without an initial commit resolves to the literal projectID "global" (ai-docs-for-opencode-v2/opencode_v2_server.md:64 and the b/ validation fixture), so a project-id key would merge unrelated directories. The anchor prescribes "key projects by host plus canonical directory", and ProjectRef's equality uses exactly the host and the canonical directory (identity.dart:163-215).
- A row without a reported directory keeps a null project and lands in a single unattributed group with a new localized header; no project is invented and the native projectID stays in the metadata as today.
- The groups appear in the first-appearance order of the server's rows, the rows inside a group keep the server's order, and the unattributed group takes its first-appearance position like any other group (one rule, no special case). The page chrome, the notices and the Load more control stay outside the groups, and the expanded row is still resolved by SessionRef, so a regroup or a quiet re-read keeps it expanded in whatever group the latest rows attribute it to.
- The header is a two-line, non-sticky header: the directory's last path segment as the title and the full canonical directory as a secondary ellipsized line (isolated so the path separators do not reorder in Arabic or Urdu). The unattributed group shows the localized label only. One new catalog key, no counts and no plurals.
- The grouping is a pure projection of controller.sessions, so the quiet re-read replaces it wholesale and the groups follow the rows the server just returned.
- Space-bunny also found the retained v1 precedent that matches the decision exactly: lib/presentation/utils/session_tab_grouping.dart groups the tabs by the canonical project key in first-appearance order, preserving the internal order.

One correction to the orchestrator's brief, now recorded: the projection does read the server's location (it keeps it in the metadata as nativeDirectory), so the change is about carrying the directory into the domain's ProjectRef, not about reading a new field.
