V2-043E planning, batch 2 of 2: Muse-spark, Gemini-38 and the frontier helper.

Muse-spark (approve of the same conclusion): the row renders the ownership the adapter proved, the adapter keeps the honest unknown, the domain owns the freshness rule and the v2 UI owns only the copy mapping; no ownership is inferred from the title, the directory, the profile, the endpoint URI, the port, the clock or the event feed; a known kind requires an OwnershipProof whose source names the observation and whose observedAt is the moment of the observation; the label is information and never feeds an authority decision. It delivers the vocabulary complete and localized, with the unreachable kinds justified one by one, and treats a later adapter proof source as the unblock rather than a missing resource for this unit.

Gemini-38: the same split of responsibilities and the same reachability table. It states the invariant that a known kind strictly requires an OwnershipProof with a nonempty source, a UTC observedAt, an optional expiresAt and an optional reference, and that a stale or expired proof degrades to OwnershipKind.unknown through effectiveKindAt(now, maxAge:). The five unreachable labels have their reasons: the 2.0.22 metadata carries no process id, client id, host id, lock lease or persistence state, so Live shared is unreachable without an external daemon proof, Owned by this host is unreachable because OpenCode does not attribute sessions to client hosts, Saved history is unreachable because OpenCode does not distinguish historical from active sessions in its metadata, and Running elsewhere is unreachable because there is no distributed lock or lease. Its steps: the five localization keys in the scoped catalog with the 14-locale copy and the generator plus --check, the exhaustive switch in the page, the optional ownership in the test fake, the widget tests (the default unknown label, all five kinds, the compact, wide, right-to-left and 2x layouts, and the label kept when the row is expanded), the focused test and analyze commands, and the documentation. Its rendering: a Text under the title separated by 4, labelSmall in onSurfaceVariant, maxLines 1 with ellipsis, aligned to the card start.

The frontier helper (helperClaude-opus-5-xhigh-F): the same evidence rule, with two decisive additions. First, the ownership kind is an authority input: CapabilityContext.denialReason (packages/codewalk_core/lib/src/capabilities.dart:73-91) accepts exactly liveShared and hostOwned as the kinds that allow a mutating capability for a SessionOwner, so claiming a kind the endpoint did not prove would open mutation authority later; the label must therefore stay display-only and a known kind must never be asserted without a proof. Second, the port and the loopback address are not evidence: 49374 is only the channel default, it can be configured and can sit behind a proxy (the fakes use 127.0.0.1:4096/proxy/), so inferring the topology from the port or from loopback is exactly the inference the domain forbids. It also reads the plan's glossary: Saved history means resuming a saved transcript in a new process, while an idle OpenCode session is still live and can be continued on the same server, so an inactive session is not saved history. Its display rule adds one more honest fallback: a list that is stale or behind shows unknown even when the row carries a known kind. Its steps: no adapter change at all, a new pure lib/features/sessions/session_ownership.dart with the 5-minute proof max age, a displayedSessionOwnership helper that returns unknown when the list is not current, the exhaustive sessionOwnershipLabel switch, a controller accessor that uses the injected clock and the stale/behind flags, the label rendered right under the title with the key session-ownership-<storageKey> in labelMedium on onSurfaceVariant without a forced maxLines and without a forced textDirection, the five catalog keys with the per-locale OWNERSHIP_COPY merged like RATE_COPY and PROJECT_COPY, the fakes and the tests, and the documentation.
