V2-043G planning, batch 1 of 3: helperCodex-6-luna-max, helperCodex-6.1-sol-xhigh-F and helperDeepSeek-41-flash-high.

helperCodex-6-luna-max: deliver the unit as a capability-gated set of five catalog-row actions (rename, delete, fork from here, mark as viewed and hide or show in CodeWalk), keeping the live and the history actions intact. The fork from a row is a fork of the full history, because the row has no message boundary, so the `before` is omitted. The server result stays authoritative: a command asks for a quiet catalog re-read and the user interface never patches the canonical session rows.

helperCodex-6.1-sol-xhigh-F: the actions are open live, continue, read history, fork from here, mark as viewed, hide in CodeWalk (a local archive) and delete (with the children-cascade warning), triggered from a contextual overflow menu on the row (a bottom sheet on a phone, a popup menu on the desktop) next to the direct primary action. Its authorization: the strict ownership requirement of the capability guard is resolved with a v2-specific session mutability authorization path that permits the owner-role actions on the valid session summaries the v2 catalog loaded. Its unread marker: the unread state is tracked from the session's `time.viewed` against `time.idle` where the session state supports it, paired with the mark-as-viewed call. Its delete: a confirmation dialog warns about the cascade of the child sessions, read with the `parentID` query, and shows the exact count. Its local hide: a persistent store on the metadata store with a `cw2.` prefix and a fail-closed schema, filtering the hidden sessions out of the active view with a "show hidden" toggle. Its optimistic behaviour: the optimistic rename and delete with an immediate update and an automatic rollback on a failure.

helperDeepSeek-41-flash-high: the most complete plan. The surface: every catalog row carries a 48x48 trailing overflow button that opens a material popup menu with rename, mark as viewed (only when unread), fork from here, hide or show in CodeWalk and delete (destructive); the tap still expands the row and the history and live stay in the expanded area; the desktop also opens the same menu on the secondary click; no mobile long press is added because the button is always visible; continue is not offered because the composer is out of scope. The availability is capability-driven and not ownership-gated: the row renders only from an adapter-declared capability set (rename, delete, fork, mark as viewed and the local archive) plus the row's own state; when the adapter cannot verify the exact 2.0.22 route set the server actions are shown disabled with the reason, and a platform with no lifecycle source shows no menu, while the local hide stays available independently of the server. The authorization: the core guard is left unchanged, because it would answer ownershipUnavailable for a mutating session owner since the v2 projection deliberately reports an unknown ownership; these commands therefore do not construct a capability context at all, and the action is authorized by the profile-bound authenticated credential, the exact-2.0.22 command client and the requirement that the row belongs to the current authoritative read of that same source. It names this an explicit and separately named path, not a hidden bypass, and rejects the two escalations: a fabricated liveShared proof, which would change the visible ownership label, and a new core authority dimension, which would broaden the guard for every adapter. The unread comes from the endpoint: the session projection gains the native idle and viewed timestamps in the metadata, a pure helper derives the unread state from them, the row shows a small indicator, and mark as viewed sends the current idle and then reconciles; no local completion badge is ported. The delete names the session, states that it is permanent, that a running execution is interrupted and that the child sessions and their descendants are deleted; a bounded direct-children read supplies the real count, "50+" at the cap, or no count line when the read fails, and the delete is not confirmed until the count resolves. The hide is local and fail-closed: a versioned list of the session storage keys under a `cw2.` key, bounded to 512 entries, read at startup, never overwritten when unreadable, never written before the first read and applied only after a successful write, with the filters active (the default), hidden and all. And there is no optimistic row patching: the v1 optimistic rename and delete with its rollback and pending-title guard is deliberately not ported, because the v2 rule is that a command's effect is observed only by the quiet authoritative re-read; the row shows a pending state and a failed command therefore needs no rollback.
