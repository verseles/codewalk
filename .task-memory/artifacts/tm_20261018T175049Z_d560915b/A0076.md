V2-043G planning, batch 3 of 3: helperGemini-38-flash-high and the frontier helper.

helperGemini-38-flash-high: the row provides the five actions (rename, delete with the cascade warning, fork from here, mark as viewed and hide in CodeWalk, which toggles to unhide when the hidden rows are shown). On a compact layout the actions are reachable from a trailing overflow button and from the action buttons inside the expanded row; on a wide layout also from the secondary click and the keyboard shortcuts; an action that is unsupported (mark as viewed when there is no idle marker or the session was already read, and any action while a mutation is in flight) is disabled with a localized reason or omitted. Its authorization: the core guard requires a known ownership for a mutating capability and the OpenCode projection honestly reports an unknown one, so fabricating a proof would break the honest display contract; the lifecycle mutations are authorized at the authenticated profile and harness boundary, and the command client itself validates the harness scope, the pinned version, the identifier and the cancellation. The unread marker: the projection extracts the native idle and viewed timestamps into the metadata as millisecond integers, a session is unread when the idle is present and the viewed is absent or older, the row shows an indicator next to the title, and the mark-as-viewed sends the extracted idle. Its delete: the confirmation is preceded by the direct-children read, the warning names the child count and says the action cannot be undone, the session is marked busy while the command runs and the card is disabled and shows an inline progress, and the row is not removed before the command answers.

The frontier helper (helperClaude-opus-5-xhigh-F): every row gains a popup menu button at its end (the more_vert icon, a 48 dp target, a tooltip and the semantics label, the key session-actions-<storageKey>), the same widget on the phone and on the desktop, and the same menu also opens by a long press on the card, by the secondary tap, by the context-menu key or Shift+F10 on the focused row, and by a semantics custom action; the tap still expands the row, the open live and the read history stay in the expanded buttons that already exist, the entries are mark as viewed (only on an unread row), rename, fork from here (the whole history, without a before), hide or show in CodeWalk and delete in the error colour. A native entry that is not available is disabled with its reason as a subtitle, and an action the endpoint does not define never appears, because 2.0.22 has no archive write; mark as viewed disappears when the row has no idle marker or was already read, and the hide is disabled with a reason when the store has not loaded or is unreadable. Its authorization: the guard's problem is spelled out, and the decision is not to touch the core guard and not to infer an ownership: rename, delete, fork and view are operations on the session record in the endpoint, which is the authority of that record, and the authorization comes from a capability set the platform builds from the verified evidence (the probed version exactly 2.0.22 whose stable routes are in the versioned contract, the IO platform and a usable credential), with the names history.rename, history.delete, history.fork and history.markViewed; before the probe or with another version they stay unknown or unavailable with a reason; the feature combines the capability's availability with the state predicates (the current list, no command in flight, the marker present); the capability is never discovered by trying a mutation, because the probe is GET /api/info; the ownership label keeps answering unknown and authorizes nothing; the ownership dimension of §6.7 is documented as not applicable to the endpoint's record operations, and the delete warns that it interrupts a running execution. The probe runs once to show the availability and again before each command, in the pattern of the history factory, and the client keeps its own version gate. Its unread marker: the projection records the native idle and viewed timestamps in the metadata, accepting only integers in the valid range and normalizing a double without a fractional part, and any other value leaves the key absent without failing the page; a pure helper derives the marker; the platform reads the state and the feature never reads the metadata keys; the row shows a small dot with the localized unread text and the key session-unread-<storageKey>; the command sends the row's observed idle, which is safe against a race because the server never marks a newer idle as seen; after the acceptance the quiet re-read runs and the dot disappears only when the server returns a viewed epoch at or after the idle; and the session.viewed event joins the catalog change kinds, so a view made in another client also triggers the re-read. Its delete: a scrollable alert dialog with the body that names the session, says the action cannot be undone and that a running execution is interrupted; the cascade warning starts as "counting the child sessions" with the delete disabled, and the count comes from the bounded direct-children read, with the exact count, the at-least form at the bound, the unknown form when the read fails (the generic warning stays and the delete becomes available again) and the authentication failure closing the dialog; closing the dialog cancels the read; on the confirmation the row and the capability are revalidated and one delete is sent; while it runs the row stays visible with the deleting status in a live region and that row's menu and buttons are disabled, while the other rows, the refresh and the Load more stay normal; the acceptance asks for the quiet re-read, the row's disappearance discards the state and shows the page notice, and a row that is still there after thirty seconds turns into the not-confirmed status.
