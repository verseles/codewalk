V2-043H planning, batch 1 of 3: helperCodex-6-luna-max, helperCodex-6.1-sol-xhigh-F and helperDeepSeek-41-flash-high.

The three plans converge on the shape of the flow: the create is a dialog (or a sheet) opened from the list, the project comes from the directories the endpoint already reported (the list's own groups), the request always carries the chosen canonical directory in the body, the client sends no model, agent, metadata or permissions, the title is the user's own, and the new session arrives through the quiet authoritative re-read.

The decisions they agree on:
- The project choice is drawn from the groups the list already shows (the endpoint's reported directories), and the flow does not accept a free-form path: a directory the endpoint has not reported is not offered, because the contract's directory is the canonical one of an existing project and an arbitrary path would create a session the list cannot attribute to a group.
- The request carries the directory in the body (the v2 contract ignores the directory header and the query parameter the v1 tree sends) and, at most, the title. The client mints no identifier by default: the endpoint's own id is used, so the row that appears is the endpoint's record and not an optimistic invention. The same-identifier replay rule is not exercised by this flow, because the flow never supplies an identifier.
- The receipt is an admission: the new session is never added to the list from the receipt; it arrives with the next authoritative read, and the list shows the endpoint's own title and project.
- A refused or uncertain create says so in the list and is never replayed; an uncertain create is reconciled by the same re-read the other commands use.
- The create is disabled while the list is not the endpoint's current answer or a command is in flight, and the reason is the same vocabulary the other actions use.

Their differences are in the presentation: the compact layout opens the choice as a bottom sheet and the wide layout as a dialog, the harness choice appears only when more than one is available, and the list's group header is the natural entry point for "create in this project".
