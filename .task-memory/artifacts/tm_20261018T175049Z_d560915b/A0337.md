## Complete Results
Official WidgetTester documentation shows two distinct steps after an interaction: pump a frame to process the action, then pump a duration to advance its animation. A single duration pump is not evidence that a just-scheduled animation has received both its initial and completion frames. Official pumpAndSettle repeatedly pumps until no frames remain and explicitly cannot settle an indeterminate progress animation; the API recommends exact necessary frame counts. Therefore tests containing a deliberate pending progress indicator should pump a finite popup transition with bounded explicit frames rather than wait for all animations to stop.
Scheduler.resetEpoch documents monotonically increasing timestamps and how epoch adjustment prevents apparent backward movement. It does not authorize application code to reset scheduler time or suppress a negative elapsed assertion. TestWidgetsFlutterBinding.reset runs at the start of a widget test but its documented implementation does not establish the local cause of an animation surviving a test boundary. Local source/stack inspection and a focused isolation check are still required; explicit disposal/unmount before a callback returns is an evidence-based hypothesis to verify, not a proven project diagnosis from web search.
