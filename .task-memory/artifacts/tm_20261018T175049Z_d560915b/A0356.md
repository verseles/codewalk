5. Resolved Decisions
1. Transport Binding Fence & Outbox Provenance:
   - Add `bindingRevision` (int, default 0, bounded 0..1,000,000) to `EndpointProfile`. Increment only on acknowledged URL changes (including same-origin path and ABA). Label-only edits preserve `bindingRevision`.
   - Persist full validated client endpoint URI string on all new `_Record` entries in `prompt_outbox_store.dart`.
   - Legacy records lacking endpoint: permit network replay/cancel/switch only when the active profile has trusted `bindingRevision == 0`. If `bindingRevision > 0` or context is untrusted, refuse network actions with `OutboxReconciliation.refused('unboundLegacyEntry')` or `OutboxMutation.refused('sourceMismatched')`. All records remain inspectable and dismissible.
   - Critique of Legacy 0 Fence: In production, `EndpointProfileStore` has always been create-only with 128-bit random IDs (`profile_` + 32 hex chars). A profile with `bindingRevision == 0` has never undergone a URL edit since creation; all historical outbox entries under that profile ID were posted to that exact endpoint. Once edited, `bindingRevision >= 1` permanently disables network mutations for un-annotated legacy entries, even if the URL later returns to the original value (ABA). The fence is provably safe.

8. Risks and Mitigations
1. Cross-Endpoint Outbox Replay / Mutation:
   - Severity: Critical.
   - Mitigation: Record full client endpoint on new outbox entries; enforce strict URI equality. For legacy un-annotated records, gate network actions by `bindingRevision == 0`. Synchronously revoke outbox on slot close and recheck before all HTTP operations.
2. In-Flight First Prompt Delivery to Stale / ABA Endpoint:
   - Severity: High.
   - Mitigation: Check `bindingRevision` in `WorkspaceDraftController.wanted()`. Any URL change increments `bindingRevision`, causing `wanted()` to fail and safely resetting draft status to ready.
3. Commit-Then-Throw Storage Desynchronization:
   - Severity: High.
   - Mitigation: In both `EndpointProfileStore` and `WorkspaceStore`, catch storage write exceptions and read back actual persisted state. If persisted content matches target, treat write as successful; otherwise flag persistence error without corrupting cached state.
4. Settings Search Query Parameter Breakage:
   - Severity: Medium.
   - Mitigation: Pass search highlight target via GoRouter typed `extra` instead of URI query parameters, preserving compatibility with `app_navigation_controller.dart`.

9. Assumptions and Fallbacks
1. Identity: Profile ID is an immutable 128-bit random token. URL and label may change; session and tab state are keyed by `profile.id` and retain local history.
   - Fallback: If profile ID is modified or missing during update, reject with `FormatException`.
2. Transport Binding: `bindingRevision` increment is the sole operational fence for transport invalidation.
   - Fallback: If stored JSON lacks `bindingRevision`, decode defaults to 0 (legacy create-only profile).
3. Vault Isolation: Scoped credentials in `EndpointCredentialVault` are keyed by canonical origin `(scheme, host, port)` and `profileId`.
   - Fallback: If destination origin has no stored credential, profile surfaces as unauthenticated; user authenticates via existing Password/Pair repair without credential migration.
4. UI Navigation: GoRouter `extra` is available during in-app push navigation.
   - Fallback: If `extra` is null (direct deep-link or drawer tap), `HostsPage` renders without highlight or auto-focus.
