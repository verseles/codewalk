# ART-EXECUTION-HANDOFF — #471: updater Android in-app (v2)

## 1. Status
Ready. No blockers. Planning-only: no code, release or workflow change is authorized here.

## 2. Problem
The v2 Android updater hands the exact APK URL to the external browser. v1 downloaded in-app with progress and opened the system installer. #471 asks for the v1 *features* re-implemented (not ported), with beta support kept opt-in and off by default.

## 3. Objective
On Android arm64, an available update downloads the exact candidate APK in-app with visible progress, verifies size + SHA-256 + release manifest, and opens the system installer. Every failure is typed and retryable, there is no browser fallback, beta remains opt-in (default stable), and Linux behavior is unchanged.

## 4. Context and constraints
- Repo `/home/helio/MEGA/WORK/codewalk`, branch `main`, HEAD `b6216deb` (local). After-mvp unit.
- Dio is forbidden outside `packages/codewalk_net/` and `packages/harness_*` (`tool/ci/architecture/manifest.dart:170`; `dio-boundary` in `dependency_graph.dart`).
- `IoEndpointHttpTransport` is origin-bound and sets `followRedirects = false` (`packages/codewalk_net/lib/src/io_endpoint_transport.dart:120`).
- Observed redirect on 2026-11-04: `github.com` → `release-assets.githubusercontent.com` (302), for both the APK and `SHA256SUMS`.
- `open_filex` 4.7.0 uses its own FileProvider with `cache-path "."`; `getTemporaryDirectory()` is the right directory; `open()` returns as soon as `startActivity` returns.
- `AndroidManifest.xml` already declares `REQUEST_INSTALL_PACKAGES` and the app FileProvider.
- `pubspec.yaml` already has `dio`, `open_filex`, `path_provider`, `crypto`, `package_info_plus`.
- Beta channel already exists: stable default, persisted at `cw2.updates.channel`, beta only after explicit opt-in; `UpdateCheckController` is check-only.
- Releases publish `SHA256SUMS` and `release-manifest.json` (schema 1: tag, version, version_code, abi, application_id, signer_sha256).
- `.v2preview` builds carry `applicationIdSuffix = ".v2preview"`.

## 5. Resolved decisions
1. **Transport**: new `dart:io HttpClient` in `lib/platform/releases/`, `followRedirects = false`, manual redirect loop, observed allowlist exactly `{github.com, release-assets.githubusercontent.com}`, max 3 hops, HTTPS only, no userinfo/fragment, query allowed only on redirects, no auth/cookies, `User-Agent: CodeWalk`, `Accept-Encoding: identity`. Connect 15 s, headers 15 s, 30 s inactivity, 15 min total, hard cap 256 MiB.
2. **Integrity**: fetch `SHA256SUMS` and `release-manifest.json` for the exact tag first (≤256 KiB each); require manifest schema 1, matching tag/asset SHA-256/size, `version_code`, `abi == arm64-v8a`, `application_id == com.verseles.codewalk`, and `signer_sha256` equal to the published production signer. Compare the streamed digest and byte count. Any mismatch/missing file: fail closed, delete the file, no browser.
3. **Downgrade**: if manifest `version_code <= installed buildNumber`, block before downloading.
4. **Flow**: Download → `.part` → verify → atomic rename to `.apk` → open the installer automatically when the app is in the foreground, otherwise `ready` with an Install button. Never call `launchUrl` on Android.
5. **UI**: inline card in Settings > Version and updates; determinate bar + percent when length is known, indeterminate otherwise; throttle at ≥1% and ≥100 ms, completion always notifies; Cancel/Retry/Dismiss; wording says "installer opened", never "installed".
6. **Beta**: unchanged existing behavior (stable default, explicit persisted opt-in); add gap tests only; never auto-enable, even for beta users or after a beta download.
7. **Package guard**: only `com.verseles.codewalk` may self-update; `.v2preview` shows the unsupported notice and performs no transfer.
8. **Cleanup**: delete `*.part` on startup; keep verified APKs (the installer may still read one after a process kill); a new download for another tag removes older verified files.
9. **Lifecycle**: no foreground service and no resume; process death becomes a clean retry. Installer cancellation is undetectable and is treated as "installer opened".
10. **Unknown sources**: rely on the system flow; map installer/permission failures to typed messages. No native MethodChannel in this scope.
11. **Selection**: `selectUpdate` and the V2-077A guards stay untouched; the controller fetches sibling integrity assets and fails closed.

## 8. Risks and mitigations
- **Trust domain**: `SHA256SUMS`/manifest share the release origin; they catch corruption/swaps, not a compromised release. Android signature (same signer) is the authenticity gate; state this plainly.
- **Mobile data**: ~89 MB; show the size and keep the action explicit; no Wi-Fi-only rule in this scope.
- **Process death**: no resume; `.part` cleanup and a clean retry.
- **OEM installer quirks**: typed failure + Retry; verify on the S25.
- **Redirect host changes**: fail closed; a policy test pins the allowlist.
- **Jank**: incremental hashing during download; final re-hash in `Isolate.run` before handoff.
- **Preview package**: package-name guard prevents replacing production.
- **#444**: its browser-failure half becomes moot; close/merge later with owner approval.

## 9. Assumptions and fallbacks
- CDN hosts stay within the observed pair; a new host fails closed and requires an allowlist update with evidence.
- `open_filex` can open a cache APK on the target devices; fallback is the app FileProvider via a small native channel, out of scope until proven necessary.
- Every eligible release publishes both integrity files; otherwise the update is not offered (fail closed).
- `PackageInfo.buildNumber` equals the Android `versionCode`.
- `crypto` supports chunked hashing (verified in pubspec; confirm in unit tests).
- Package name is `com.verseles.codewalk` in production.

## 10. Out of scope
- Linux/desktop install execution, Windows, macOS, iOS, Web.
- Background/foreground-service downloads, resume, system notifications, `PackageInstaller` sessions.
- New releases, tags, workflows, `make_latest`, `/releases/latest`.
- Changing V2-077A selection or the beta policy.
- Porting v1 code or legacy imports.
- Closing #444 or editing `v2-plan.md` rows without owner approval.
