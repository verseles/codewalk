Todos existem com superfície oficial. Pi: Earendil Works (earendil-works/pi, ex badlogic/pi-mono), MIT, 1.0.0 em 2026-10-01; RPC JSONL stdio (pi --mode rpc) via bridge no host; sem sistema de permissões por design, sem todos/subagentes/listagem de sessão/busca de arquivos nativos (precisa extensão Pi fornecida pelo CodeWalk); community pi-acp adapter. Muse Code: Meta, lançado 2026-08-05/06, v1.4.2, CLI fechado, SDK+schema MIT; Muse Session Protocol v1 (muse serve) stdio sem transporte de rede nem auth; protocolo mais completo p/ GUI: approvals, questions, list/resume por cursor/fork, steer/queue, todos, subagentes, janelas de cota 5h/semanal; sem ACP oficial. Grok Build: xAI, Apache-2.0, npm 1.0.46; ACP sobre WebSocket nativo: grok agent serve --bind --secret (ws:// sem TLS, segredo único -> Tailscale/VPN/TLS proxy); extensões x.ai/* (fork, rewind, mid-turn, file search, fs, git, terminal, billing, ask_user_question) instáveis. DeepSeek Harness dsh: oficial DeepSeek, MIT, preview 0.2.0-rc.2 com breaking changes; ACP stdio (dsh --profile acp) fino: resume sem replay, sem slash/plans/questions/steer/fork; recursos ricos só na web UI interna loopback; recomendação: adiar. Ecossistema: ACP é o protocolo comum; registry oficial lista 42 agentes (Gemini CLI, Qwen, Kimi, Copilot CLI, Cursor CLI, Droid, Goose, OpenCode, Codex, Claude Code, Mistral Vibe, Amp...; Muse e dsh fora). Outros protocolos: Copilot SDK TCP headless, Codex WS experimental, goosed REST+SSE -> goose serve, Kimi Wire JSON-RPC, Amp stream-json, Crush sem ACP. Conclusão do agente: 1 cliente ACP no CodeWalk + 1 bridge stdio->WebSocket no host cobre Grok, dsh, Pi (pi-acp) e muitos outros. Sem lib Dart de ACP pronta. Incertezas: adapter Zed do Muse, plataformas Muse (Linux?), hosts de install Muse, licença Grok no registry, payload x.ai/ask_user_question, capability de imagem Grok, SDK dsh.
