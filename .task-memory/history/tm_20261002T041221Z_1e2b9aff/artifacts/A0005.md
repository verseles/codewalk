Superfície recomendada: bridge no host (Node/Bun) com @anthropic-ai/claude-agent-sdk TS (0.3.287), sessão longa por sessão em streaming-input; expõe WS ou HTTP POST+SSE ao celular passando mensagens SDK quase intactas (padrão do guia de hosting da Anthropic). stream-json do claude -p é o mesmo protocolo, semi-público e mutável. Sem daemon de rede oficial utilizável (Remote Control/cloud só via claude.ai; --sdk-url só aceita servidores Anthropic). Protocolo rico: 39 tipos de mensagem de saída e 40 control requests; sinal busy/idle/needs-input; eventos de cota do plano + leitura de uso experimental; permissões allow/deny/updatedInput/regras salvas/troca de modo ao vivo; AskUserQuestion e aprovação de plano via callback de permissão; interrupt com lista de mensagens enfileiradas; mensagens mid-turn enfileiradas no turno; subagentes e shells em background com eventos start/progress/finish, stop por task; rewind de arquivos. Happy e CloudCLI usam SDK+bridge; Omnara abandonou wrap. Gaps que a bridge cobre: listagem/busca de arquivos p/ @, git diff, terminal, push, log de eventos com replay, health via claude auth status --json; sem redo; todos desligados por padrão em modelos novos (CLAUDE_CODE_ENABLE_TODO_TOOLS=1). Política: permitido com condições (usuário loga na própria máquina via claude auth login/setup-token ou API key; binário oficial inalterado; uso de SDK/terceiros consome limites da assinatura per Help Center jun/2026). Proibido: login Claude in-app, coletar/encaminhar OAuth tokens, APIs do Remote Control, modificar binário, se passar pelo cliente oficial, chamar a feature de "Claude Code". Risco: Anthropic diz que ferramentas de terceiros devem usar API keys -> oferecer modo API key. Incertezas: bug #98713 (stop após msg em turnos posteriores ignorado, CLI 2.1.286), session id divergente em --resume, permission mode default auto (sempre passar), regra abr/2026 de harness terceiros pagando extra, exibir cota própria, campos ao vivo (stop_reason etc.). Sugestão: captura scriptada de stream-json antes de implementar.
