V2-043B planning, batch 1 of 2 (3 of the 6 ready helpers delivered).

helperDeepSeek-41-flash-high - Option B: a catalog-owned, bounded lifecycle subscription per selected profile, separate from the live directory, behind a new shared port (session_list_signal_source.dart + a pure codec + the IO factory + a conditional stub). The live owner is rejected as a trigger because it drops every frame whose session is not watched (stream_owner.dart:484) and its per-profile slot is closed when the last live handle is released, so the list would lose updates exactly when no session screen is open. A second subscription is contract-safe: the server keeps one bounded dropping queue per subscriber (4,096) and an overflow disconnects only that subscriber; 'one global SSE stream' describes the endpoint scope, not a single-client limit. Triggers: session.created, session.renamed, session.deleted and session.forked (forks do not emit created). Re-read: the existing refresh path with a quiet variant (cursor null, limit 50, page 1 only) that does not set stale/refreshing and preserves a still-present expanded row. Policy: a 300 ms one-shot debounce that is not reset, at most one pending re-read latched, a 1 s minimum interval between reads. Failures: a signal failure never clears rows and never sets the catalog failure; a new 'live updates paused' notice appears; a reconnect always forces one authoritative re-read; a failed quiet re-read keeps the rows and marks them stale. Adds one l10n key across the 14 locales.

helperGrok-47-medium - share ONE GET /api/event per endpoint profile with the live directory: add a catalog hold on the same _ProfileSlot (probe 2.0.22, start the existing owner, never call watch) and give the owner a payload-free lifecycle trigger emitted before the watch filter, so unwatched lifecycle frames reach the list. It rejects a second subscription as the wrong steady state (two connections, two independent reconnects, the list and a live screen could disagree about a gap) and notes that V2-044B2 and session_live_directory_test.dart already require one stream per profile. Coalescing: one dirty bit, never a queue, at most one read in flight plus one follow-up, a 300 ms trailing debounce, a 1 s floor between follow-ups, and after 8 completed follow-ups that were still dirty the automatic follow stops and the list stays stale until a manual refresh. The re-read is a first-page refresh, not a cursor replay, and the loaded pages beyond the first are dropped; the selection survives only if the ref is still present. No new locale key: reuse sessionsPreviousResults. The stub keeps a null directory and stays pull-only; no RefreshIndicator is added.

helperSpace-bunny-max - a second dedicated bounded subscription owned by the catalog source itself (the SessionCatalogSource port gains one broadcast stream of canonical signals; the IO source opens one IoSseRecovery on api/event and classifies frames). It rejects reusing the live owner for the same reasons as DeepSeek (the owner discards unwatched frames, the slot dies with the last live handle, it hydrates a store the catalog does not need) and rejects polling. A second subscription is contract-acceptable (a per-subscriber bounded queue, a slow subscriber is dropped alone); the cost is one extra long-lived connection per selected profile, only while a profile is selected. The re-read is the same GET /api/session read through the same source but REPLAYS the loaded scope (page 1 plus the stored opaque cursor chain) and is applied atomically, so a user who loaded three pages keeps three pages; a failed cursor degrades to the pages that succeeded. A read in flight holds the trigger as a single pending flag and the re-read starts after it settles; the existing generation fence prevents a superseded read from publishing rows. The expanded row survives only if it is still in the authoritative result.
