Orchestrator judgment of the V2-043B planning round (6 of 7 eligible helpers delivered; helperGemini-4-argon-medium-F failed twice with SESSION_GEMINI_ERROR and produced no plan).

ACCEPTED (the consensus direction): the session list becomes live through a payload-free catalog signal derived from the session lifecycle events (session.created, session.forked, session.renamed, session.deleted), and every signal triggers an authoritative re-read of GET /api/session. No row is ever built from an event. The re-read is quiet: it does not set loading or stale, it does not show progress, and the expanded row survives only while the session is still present.

CORRECTION APPLIED TO FOUR PLANS: DeepSeek, Space-bunny, Muse-spark and Gemini-38 all recommend a dedicated second subscription to GET /api/event. That contradicts an accepted project decision the orchestrator's payload did not include and the frontier plan surfaced: v2-plan.md fact 4 states the consequence 'One stream per endpoint; buffer + hydrate on every reconnect; never assume continuity'. A second concurrent subscription for the same endpoint violates it, so the direction is the one Grok and the frontier plan chose: reuse the single per-profile stream through a catalog lease on the per-profile slot, with the owner emitting the payload-free catalog signal at the start of its frame handling, before _routeChild and before the watch filter, so no lifecycle frame is consumed before the signal. The four plans' other content (the trigger set, the authoritative re-read, the coalescing policy, the failure isolation) is accepted and folded into the handoff.

USEFUL/COMMON: Muse-spark's coalescing (one timer about 500-750 ms plus a dirty flag) and Gemini-38's 300 ms debounce with a 1,500 ms flood ceiling, both compatible with the handoff's 300 ms debounce plus a 2 s cooldown.

REJECTED/UNSUPPORTED: a dedicated second subscription (it breaks an accepted project decision, though it remains the documented fallback if the shared-stream extraction proves unsafe); the periodic poll (it contradicts the contract's event stream and spends mobile battery); a 'quiet' re-read that keeps the older loaded pages untouched (it would leave a deleted row visible, which is dishonest); and a new locale key for the paused state (the existing liveStale string covers it).
