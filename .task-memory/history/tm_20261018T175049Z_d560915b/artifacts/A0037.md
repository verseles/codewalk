V2-043C review round 1, batch 1 of 2 (DeepSeek, Grok, Space-bunny).

All three delivered a schema-valid report with the same verdict: fix_required, overall_risk medium, confidence high. They converge on the same real defects, which the orchestrator verified against the code:

A. The automatic re-read is not single-flight. _runLive blocks only on `loading`, and the quiet path never sets it (it sets _quietRefreshing), so a change arriving during a quiet read starts a second full-depth traversal (up to 10 GETs). The older traversal can then overwrite the newer one, and the failures double-count toward the three-failure suspension. Grok and Space-bunny add that a manual `load more` during a quiet read does not bump the generation, so the quiet result replaces the list with the depth captured before the tap and the page the user just loaded disappears. Fix: treat _quietRefreshing as in-flight, keep the pending latch for one follow-up, re-arm the latch when the quiet read settles, and let the manual paging supersede the quiet read.

B. The connection mapping is wrong in two ways. The lease forwards every OpenCodeConnectionUpdated and maps everything that is not `live` to disconnected, so a per-session degradation (the owner emits degraded with a session when one watched session cannot be hydrated) marks the whole list "not up to date" although the endpoint stream is healthy. The owner also emits `hydrating` before `live` on every connect, so each fresh connect would show the notice. Fix: the lease forwards only stream-level updates (session == null) and the controller treats the connection as a transition, so only a real drop marks the list behind and only a real reconnect schedules the catch-up read.

C. A failed or superseded read still marks the list behind and can suspend the automatic updates. _readLivePages returns null when the generation or the epoch no longer matches, but a throw from the task skips that check, so the catch always increments the failures, sets _behind and may set the suspension. Fix: apply the failure, the suspension and the cooldown only while the read is still current.

D. The catalog feed acquisition is not single-flight, so two overlapping acquisitions replace _changes without closing the older feed: the orphan lease keeps the endpoint's slot and event stream open after the profile is left. Fix: keep one in-flight acquisition and never replace _changes without closing the previous feed.

E. The "not up to date" notice survives a successful authoritative read: the manual read's success branch resets the failures and the suspension but never `behind`, and a failed manual refresh's error banner also survives a successful quiet re-read. Fix: clear the notice on any successful authoritative read, manual or quiet, and clear the catalog failure on a successful quiet re-read.

F. A session created between the list's read and the feed's subscription is lost, because the server does not replay and the feed opens after the read. Fix: arm one pending re-read once the feed is established.

G. Two smaller records: the quiet re-read silently drops the rows past 200 without setting `limited` (the manual read reports it), and the closed leases are retained in the slot's list until the slot itself closes.

H. One documentation/guard item: the unit added a narrow `// ignore: cancel_subscriptions` on the feed's subscription. The orchestrator keeps it, because the project's rule is "no lint or test suppression without a narrow justification" and the cancellation is explicit in _closeChanges; the justification is recorded in place and in the Task Memory.

Accepted tradeoffs all three recorded: one stream per endpoint (the lease only listens to the owner's signal and the owner's connection updates, the directory keys the slots by profile|endpoint, and the new test asserts a single event request while the feed is held); the payload-free signal; the quiet re-read that sets neither loading nor stale; a change during a read becoming one final read; the rate-limit and three-failure suspension; the mechanical extraction of the live runtime into its own file for the 1,500-line guard.

Non-issues recorded: the extraction is mechanical (the blob diff shows only the renames plus the lease holder count); the web stub keeps the catalog pull-only through the null live directory; the liveStale locale key already existed in every ARB; the guard still passes; the duplicate-ref rejection in the quiet read mirrors the manual read.
