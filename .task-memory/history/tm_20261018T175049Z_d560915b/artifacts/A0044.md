Problem: the v2 session list is flat. SessionsPage renders one card per loaded session in the server's order, with no grouping, and the domain's ProjectRef (the host plus the canonical directory the server reports for a session) is never filled: the projection keeps the server's projectID and location.directory in the metadata and leaves SessionInfo.project null.

Objective: the v2 session list groups the loaded sessions by their project, with a group header per project, on the compact and wide layouts, following the server's order, with the sessions the server did not attribute still listed.

Resolved decisions:
D1 - The group key is the ProjectRef identity: the endpoint host plus the server-reported canonical directory. The server's projectID is carried only as the upstreamProjectId annotation and never merges two directories.
D2 - The projection fills SessionInfo.project with ProjectRef(host, directory, upstreamProjectId: projectID) from the record's location.directory. A record without a location, with a non-string directory or with an empty directory keeps a null project; the metadata keeps nativeProjectId and nativeDirectory exactly as today.
D3 - A session the server did not attribute lands in a single unattributed group, whose header is the new localized key. No project is invented.
D4 - The groups appear in the first appearance of the group's first row in the loaded list, and the rows inside a group keep the server's order. No alphabetical or time-based re-sort: the retained v1 reference groups by the canonical project key in first-appearance order, and the server's own order is newest-first.
D5 - The group header is server content: the canonical directory verbatim, with the directory's last path segment as the title and the full directory as a secondary ellipsized line, isolated so the path separators do not reorder in Arabic or Urdu. The header is not sticky and carries no count. The unattributed header shows the localized label only.
D6 - The grouping is a pure projection of controller.sessions, computed where the page renders it, so a quiet re-read regroups the rows the server just returned and the expanded row (resolved by SessionRef) keeps its group. The header block, the notices and the Load more control stay outside the groups.

Risks and mitigations:
- The index arithmetic of the list changes: a wrong mapping would drop a card or the Load more control. Mitigation: the flattened sequence is computed once per build and covered by the widget tests for every item kind.
- The path in the header can be long or RTL: mitigation: the last segment as the title, the full path ellipsized, the text isolated, and the compact and RTL cases in the tests.
- The server may report a location that is not a directory: mitigation: the projection accepts only a non-empty string and keeps the project null otherwise.
- The l10n catalog and the generated output can drift: mitigation: the generator check is part of the validation.
