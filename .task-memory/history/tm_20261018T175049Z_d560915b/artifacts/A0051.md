V2-043E planning, batch 1 of 2: DeepSeek, Grok and Space-bunny.

CONSENSUS (all three): the v2 row renders the ownership label the row's own evidence supports, and for an OpenCode session the only label reachable today is *Ownership unknown*. The three plans agree on the split of responsibilities: the adapter owns the claim and its proof (it keeps reporting the honest unknown and emits no proof), the domain owns the freshness math (a known kind requires an OwnershipProof and a fresh one), and the authored v2 UI owns only the kind-to-copy mapping. No plan infers ownership from the title, the directory, the profile, the endpoint URI, the port, the clock or the event feed, and no plan treats a successful GET /api/session, a connected profile, port 49374 or 4096, GET /api/info pid or urls, projectID, location.directory, time.idle or time.viewed as proof.

DeepSeek: the label is rendered from the row's OwnershipInfo, with a known kind requiring OwnershipInfo.known(kind, proof) whose source names the adapter observation and whose observedAt is stamped at read time; the UI additionally requires a fresh proof (a display-only 5-minute max age) and falls back to unknown for a null, missing, expired or stale proof; rawKind stays diagnostic and never becomes a label. Rendering: a separate always-visible line under the title inside the row Column, before the expanded block, start-aligned, labelMedium in onSurfaceVariant, wrapping, with the key ownership-<storageKey>; the title keeps its collapsed maxLines 3 and the expanded date/history/live content stays below. The five labels are unreachable for OpenCode for five verified reasons (no execution marker, no local/remote/service kind on the profile, the persistent index also returns running sessions, the lifecycle stream is payload-free and anonymous, no other-client evidence). Steps: extend the scoped catalog with OWNERSHIP_KEYS/OWNERSHIP_COPY and regenerate with --port-sessions then --check; render the label; extend the test fake with an optional OwnershipInfo defaulting to the current unknown; add widget tests for the unknown label in every locale and layout, the five known labels with fresh proofs, the stale/expired fallback, the 2x RTL wrapping and the label changing after a quiet re-read; then the focused commands, make check once (the generated localization files change) and the documentation. Its risk note: the honest outcome is that every OpenCode row shows Ownership unknown, so the label's product value depends on a future adapter proof source.

Grok: one ownership label per visible row, taken only from that row's SessionInfo.ownership and decayed by the domain's freshness rule (a fresh proof: nonempty source, observedAt not after now, age at most 5 minutes, and now strictly before expiresAt when set); a missing, stale, future or expired proof renders Ownership unknown and the diagnostic reason is never shown. The OpenCode adapter keeps reporting the unknown with its current reason string; rename keeps the resident ownership and must not invent a kind. It lists the same four unreachable labels with their reasons and warns specifically against treating the history action as saved history and against the archive marker, which is out of scope. Where the decision lives: classification in harness_opencode (the only layer that sees the native record), freshness in OwnershipInfo.effectiveKindAt, and only the kind-to-string mapping in the v2 UI, which must not read the endpoint URI, port, pid or native metadata. Steps: a new lib/features/sessions/session_ownership_label.dart with the 5-minute max age and an exhaustive switch; expose the controller's injected clock as DateTime get now (the page must not call DateTime.now() itself); render the Text under the title with the key ownership-<storageKey>, bodySmall, onSurfaceVariant, maxLines 2 and ellipsis; extend the scoped catalog like RATE_COPY and PROJECT_COPY and regenerate; extend CatalogSource.row with an optional OwnershipInfo; keep the adapter assertions that the projections stay unknown with a null proof and do not change the reason string; then the focused commands, make check once and the documentation. It records that the unit is not blocked: showing Ownership unknown on every current OpenCode row is the intended final behaviour, and a later unit can surface another label only after an adapter supplies a real proof.

Space-bunny: the label is a projection of the row's own OwnershipInfo and the UI never infers ownership from the title, the canonical directory, the profile, the endpoint URI, the port, the clock or the event feed; the adapter reports the ownership it can prove (a known kind requires an OwnershipProof whose source is the observation and whose observedAt is the moment of observation), the domain enforces known-implies-proof, and the UI only maps the kind to the plan's vocabulary; the label is information, not permission, and never feeds an authority decision. It verifies the same four unreachable labels and adds one decisive piece of evidence: liveness is proven by GET /api/session/active ("Retrieve foreground Session drains currently owned by this OpenCode process. Sessions absent from the result are inactive", plan/opencode-v2-src/protocol-groups/session.ts:271-278), which is a NEW server query that this unit excludes; the pinned Session.Info has no runtime or liveness field. It also shows that the v2 domain has no identity for the client's own device (HostId is an app-assigned id set to the profile id; a loopback URI is not the device's own host on an Android emulator), which is why Owned by this host is unreachable, and that time.idle is the outcome of the last completed execution, not the current state. Its consequence: in production every OpenCode row shows Ownership unknown in this unit, the vocabulary is delivered complete and localized, and a later bounded unit that reads the endpoint's active-session list is what makes the other kinds reachable. It raises one product decision for the owner: accept the uniform Ownership unknown for V2-043E, or open a follow-up issue for the active-session read. Steps: confirm the contract surface with no code change in core or the adapter; add the pure label projection with an exhaustive switch over ownership.kind; render the label right after the title with the treatment the v2 permission card already uses (Padding top 4, labelSmall in onSurfaceVariant, maxLines 2, ellipsis, key session-ownership-<storageKey>); then the catalog, the tests, the checks and the documentation.
