Orchestrator assessment of the V2-043F planning round (eight of the nine eligible helpers delivered a plan; helperGemini-4-argon-medium-F failed its handshake and its retry because its backend quota is exhausted, as the owner confirmed).

AGREED BY EVERY PLAN: one harness client with the five commands and no change under lib/ (the profile slot is already 1,467 lines, so it cannot host the new code); every attempt carries an OriginalCommand, a CommandReceipt and, when the contract returns a body, the projected SessionSummary; a receipt is the admission of one HTTP exchange and never proof of an effect, because the effects are server-side and are observed by the stream or by an authoritative re-read; the client never retries, replays, persists or updates the catalog; the domain vocabulary is additive only, with MutationOperation gaining exactly a rename and an unread-marker member before unknown and no existing member changing meaning; archive stays the local hide, because v2 HTTP exposes no archive write; the client never mints a session id, it accepts an optional caller-supplied one or omits the key; the create body always carries location.directory and never a directory header; the error bodies are never read, because native messages echo ids and paths, so the refusal comes from the status alone and the reasons come from a fixed vocabulary; and the commands are gated fail-closed on the connected version.

DECIDED ON THE EVIDENCE
D1 - One client, not five. The five commands share the transport, the connected version, the deadline, the body bound, the ownership assertion, the command and receipt construction and one status vocabulary; five classes would duplicate roughly 120 to 180 lines each and fork the vocabulary. One file, one private send core, one attempt type with optional fields.
D2 - The version gate is exactly 2.0.22. The sibling mutation clients already refuse anything else (prompt_client.dart:129, form_reply_client.dart:131) with unavailable('unverifiedVersion'), and ADR-023 forbids sending to a version whose command path was not verified. The policy minimum of 2.0.20 and the tested 2.0.21 are insufficient: the fork shape, the view body and the same-id create semantics are verified only on the 2.0.22 anchors.
D3 - One attempt type, with the session and the payload as optional fields.
D4 - The create body carries only the optional id, the optional title and location.directory. The agent, the model, the metadata, the permissions and the 2.0.22 parentID are never sent, and a request that carries a field this unit cannot send is refused as an unsupported create instead of silently dropping it.
D5 - The same-id create occupancy rule. The recorded matrix (test/contract/fixtures/opencode/2.0.22/b/create-matrix.json) shows that a create replay with a changed title answers 200 with the original session and the original fields, the new ones ignored. So a 200 whose title or directory differs from the intent is not the session the client asked for: it becomes a rejection with the reason SessionIdentityOccupied and the action refresh.
D6 - The method names are create, rename, delete, fork and markViewed; the domain's operation names are the source of truth for rename and markViewed, and delete keeps the domain's name.
D7 - The client does not call the capability guard, does not implement HarnessAdapter.create and does not extend LifecycleFacet. The sibling clients authorize a harness match alone, and a session's metadata ownership is always unknown, so the capability guard would deny every call; the authorization belongs to the later row-action unit.

ACCEPTED TRADOWNS
The catalog and the list are not wired to these commands in this unit, so the commands have no user-visible effect yet; the effects of a command are observed later by the stream or by an authoritative re-read; the fork and the view commands have no live recording, so they are tested against fakes in the contract's shape and the missing recording is recorded as a risk.

REJECTED
Five separate clients (helperCodex-6-luna-max); the 2.0.20 minimum gate (helperCodex-6-luna-max); one attempt class per operation (helperGemini-38-flash-high); and any reading of the command as a permission to mutate, since the domain's capability guard owns that decision.
