OBJECTIVE: the v2 harness sends the official 2.0.22 session lifecycle commands - create, rename, delete, fork and mark-as-viewed - with the exact request encoding, the status mapping and typed failures.

DECIDED (do not reopen without new evidence)
D1 - One client: OpenCodeSessionLifecycleClient in a new packages/harness_opencode/lib/src/session_lifecycle_client.dart, with the five public methods create, rename, delete, fork and markViewed over one private send core that copies the interrupt client's pattern (its own cancellation token, the expiration completer, the Future.any, the late-response cancellation and the finally that cancels the timer, the listener and the response). One attempt type for all five methods.
D2 - The version gate is exactly 2.0.22: OpenCodeCompatibility.parse(connectedVersion)?.toString() != '2.0.22' answers unavailable('unverifiedVersion') and nothing is sent. The general compatibility table is untouched.
D3 - The domain gains MutationOperation.rename and MutationOperation.markViewed, inserted immediately before unknown; create, fork, delete and archive keep their meaning, and archive is never sent over HTTP in this unit.
D4 - A receipt is an admission, not an effect. The attempt carries the OriginalCommand, the CommandReceipt, the exact JSON payload only when bytes were handed to the transport, and the projected SessionSummary only when a contract 200 body was parsed (create and fork). No method retries, replays, persists or updates the catalog.
D5 - The create body carries only the optional id, the optional title and location.directory, which is always present; a request carrying a field this unit cannot send is refused as an unsupported create instead of silently dropping it. The client never mints a session id.
D6 - The same-id create occupancy rule: a 200 whose title or directory differs from the intent is a rejection with the reason SessionIdentityOccupied and the action refresh, because the recorded matrix shows the server returning the original session with the new fields ignored.
D7 - The error bodies are never read. The status alone decides: 400 rejected as a protocol error with InvalidRequestError, 401 and 403 rejected as an auth error with UnauthorizedError, 404 rejected as a protocol error with SessionNotFoundError, 429 rejected as a rate limit with RateLimited, and any other status uncertain. The raw message is always empty and no reason carries a directory, a title, an id, a URL or a token.
D8 - No change under lib/: the client does not call the capability guard, does not implement HarnessAdapter.create and does not extend LifecycleFacet. The authorization belongs to the later row-action unit.
