V2-043G planning, batch 2 of 3: helperGrok-47-medium, helperSpace-bunny-max and helperMuse-spark-13-xhigh.

helperGrok-47-medium: the expanded and the collapsed row keep the history and the live buttons and add one overflow control, which opens a modal sheet on a compact width and a menu anchored to the row end on a wide one; both offer the same actions in the same order and no others (rename, fork from here, mark as viewed, hide in CodeWalk and delete), and dismissing them does not select the row. The server actions run only through a neutral catalog-command port: the port probes the selected endpoint once and allows rename, delete, fork and mark-as-viewed only when the probe is exactly the lifecycle client's verified version, and it refuses again before the send when the list is stale or behind, when a command for that row is already in flight, or when the mark-as-viewed has no idle epoch. The ownership label stays display-only and CapabilityContext.denialReason is neither used nor weakened, because an OpenCode row is always an unknown ownership and that guard would deny every session owner mutation, while the domain defines the ownership as evidence and not as permission; the exclusive ownership stays required for the live attach, the send and the interrupt, and these catalog commands are authorized by the adapter version, the current list state and the platform presence, with the §6.7 intersection excluding the exclusive-ownership axis because the contract defines them on a shared service. The unread is the idle present and the viewed absent or behind, with the exact epoch milliseconds; the badge is a localized label on the collapsed row, and mark as viewed sends that exact idle and does not change the badge until the quiet re-read returns a viewed epoch that is no longer behind. No server action patches a row: the row, the title and the grouping stay as the last authoritative page while the command runs, only that row's actions disable and a pending label shows; an accepted receipt requests the quiet re-read, a rejection leaves the row and shows a finite localized copy mapped from the receipt, and an uncertain receipt shows that the effect is not confirmed, requests the same re-read and is not retried, so a failed command has nothing to roll back. The delete confirmation stays disabled until a descendant walk finishes: an exact count is shown as that number, a walk that hits its bound shows "at least N" and still allows the confirmation because the endpoint delete remains defined, and a failed walk does not assume zero and does not enable the confirmation; the warning says the count is not a lock and that the server deletes every child it finds. The fork copies the whole history, with no before message id, because the row has no timeline position. The hide is local, immediate and reversible from the archived filter and from an undo.

helperSpace-bunny-max: the catalog row gets one action menu with five entries (rename, fork from here, mark as viewed, hide or unhide in CodeWalk and delete), while the read history and the open live stay where they already are so the menu does not duplicate them. The menu is a vertical list with an icon and a localized label, opened by a trailing overflow icon button on the phone, by a long press on the row, by the secondary tap, the right click and Shift+F10 or the context-menu key on the desktop, and by a semantics custom action. The v1 widget is a reference and not a port: it imports the v1 l10n and the v1 types, and its fixed 56x48 icon grid does not survive a 2x text scale, long localized labels or right-to-left, so the v2 tree re-implements the same affordances importing nothing from the retained tree. Its authorization is the hard part: the guard denies a session-scoped capability whenever the ownership kind is unknown, and the OpenCode projection always reports an unknown ownership, so every one of these mutations would be refused, and so would every read, because the same branch fires for the non-mutating contexts. Its reading: the guard's ownership dimension is a multi-client topology fact and not a permission to mutate, the domain says so, and the V2-043E delivery states that the label is display-only and never authorizes an action; meanwhile the capability set and the context have no production consumer at all today, so this is their first production use and they may be shaped additively. Its decision: extend the core guard with an explicit, freshness-bound mutation authority proof, do not weaken the ownership path and do not bypass the guard. The scoped evidence gains an optional mutation authority proof; in the denial reason, for a mutating session owner, the session is authorized when the ownership kind is live shared or host owned (unchanged) or when the mutation authority is fresh, and otherwise the reason becomes a new distinct one while the old ownership reason keeps its meaning for the non-mutating path. Everything else in the guard stays, including the owner scope, the connected version, the negotiated, model, policy, platform and state axes, the mutating requirement and the default deny. The OpenCode adapter supplies the authority from the profile's own version probe, which already fails closed unless the version is exactly 2.0.22, so the authority can never outlive a verified version. The button state and the enforcement read the same capability set and context, so they cannot disagree.

helperMuse-spark-13-xhigh: offer the five row actions next to the existing open live and read history (continue stays out, because the composer and the send unit own it); authorize by the resident session scope plus the 2.0.22 version and the credential fences and not by the capability context ownership proof, keeping the ownership labels display-only; carry the viewed and idle timestamps in the list projection for the unread dot and let the mark-as-viewed echo the row's observed idle; patch no row optimistically, with a pending state and the quiet authoritative re-read reconciling every command; and keep the local hide in a new hidden-session store with a fail-closed unreadable handling and the active, hidden and all filters.
