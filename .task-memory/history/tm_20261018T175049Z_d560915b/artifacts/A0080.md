helperGrok-47-medium: fix_required, medium risk, high confidence. The local hide, the filter and the overflow menu are wired, but the native row commands stay unavailable on the normal session path, an uncertain or suspended command is not reconciled, and the unread mark does not follow the idle transitions. Its findings: (1, warning, correctness) the commands stay disabled after a normal profile select, because the source is created once from the in-memory hosts assessment, the hosts' load never probes or fills the assessments, and the source caches that null version as unverified; the fix is to observe the profile with the existing read-only probe when the source is created and to replace the source when the observed version changes. (2, warning, correctness) a command whose receipt is uncertain, or an accepted command while the live refresh is suspended, leaves the list on the last server page, because the re-read is scheduled only for the accepted outcome and the suspension drops the schedule, and the menu ignores the outcome; the fix is to schedule one quiet authoritative re-read that the suspension does not drop, never resending the command, and to surface the refused and uncertain outcomes on the row. (3, warning, correctness) a session that goes idle does not become unread until an unrelated catalog event or a manual refresh, because the idle is published as the three terminal execution events and the slot forwards only the catalog changes; the fix is to treat those events as catalog changes and keep the shutdown-without-idle out of that set. (4, warning, regression) the desktop and the assistive-technology users cannot open the row menu the way the unit specified, because the card's ink well has only the tap and the popup button has no long press, secondary tap, Shift+F10 or context-menu handler, and the row adds no semantics custom action; the fix is to open the same menu from the long press, the secondary tap and the context-menu key or Shift+F10 on the focused row and to expose that action as a semantics custom action, keeping the primary tap as the expand. (5, warning, edge_case) after an unreadable hide list the sessions the user hid reappear in the default filter, because the unreadable read clears the list and the writes are refused, so the user can neither keep nor restore the hide; the fix is to keep the persisted list untouched and to show a store-unavailable state instead of the active filter. (6, suggestion, correctness) the delete is the destructive entry and is drawn like the rename and the fork, so the error colour is not a cue before the confirmation.

helperSpace-bunny-max: fix_required, high risk, high confidence. The unit wires the v2 row actions to the 2.0.22 contract correctly, but two defects block the feature in normal use: the composition root imports the io-only action source, which breaks the v2 Web build, and the version gate reads a hosts assessment that is empty after every app restart, so all the native actions stay disabled; the command and the local-hide failures are also swallowed with no user feedback, and the row's long-press, secondary-tap, keyboard and semantics entry points are missing. Its findings: (1, critical, regression) the composition root imports the io-only action source, which pulls dart:io into the v2 Web build, and every other platform-specific dependency of the composition root goes through a conditional-import shim; the fix is to add the shim and to import it. (2, critical, correctness) after every app restart the native row actions stay permanently disabled with the reason that the endpoint's version is not verified, because the version is captured once when the source is built and the source memoizes the probe result, so even a later manual check does not revive the actions; the fix is to let the action source obtain the version itself from the profile's own probe, as the live profile slot does, and to cache that observed version per source. (3, warning, correctness) a refused or uncertain command and a failed local hide write close the menu with no message, and the added failure and pending strings are never rendered; the fix is to keep the last non-accepted outcome in the controller and to render it in the page's notices, and to surface a failed local hide with the same notice. (4, warning, correctness) the row actions are reachable only through the trailing overflow button, and the delete entry is not rendered in the error colour; the fix is to wrap the row in a secondary-tap detector, the context-menu and Shift+F10 shortcuts and a semantics custom action, and to render the delete in the error colour. (5, suggestion, maintainability) if the action source is torn down between the null check and the dispatch, the null assertion throws instead of the command answering unavailable; the fix is to capture the checked source in the closure. Its accepted tradeoffs: no command patches a row; the unread marker rides on the summary; the fork copies the whole history; and the local hide list is bounded and refuses further hides instead of evicting an already hidden session. Its non-issues: the mark-as-viewed epoch round-trip is consistent, the delete cascade count is bounded by the endpoint's own child-page limit and the copy switches to the at-least wording at the cap, the architecture guard passes for the new files, and the delete's count is advisory.

helperMuse-spark-13-xhigh: fix_required, medium risk, high confidence. The row actions match the 2.0.22 contract and fail closed, but the alternative row activation is missing, the action version can go stale, and a few small user-feedback and error paths need fixes. Its findings: (1, warning, correctness) the long press, the secondary tap, the context-menu key and the semantics action do not open the menu, and only the small overflow button does; the fix is to wrap the row in a focus and ink well with the long press and the secondary tap opening the same menu, plus a semantics custom action. (2, warning, correctness) the actions can stay disabled after a later successful probe until the profile is re-selected, because the source is created once with the assessment's version and the support is cached, and the hosts' change handler ignores a later version change; the fix is to recreate or re-probe the source when the assessment's version changes. (3, warning, edge_case) pasting a title over the bound throws and escapes as an unhandled async error, because the rename accepts unbounded text and the controller's dispatch does not map the argument error to an outcome; the fix is to map it to unavailable. (4, warning, correctness) the screen reader always announces the filter as the active one regardless of the selected hidden or all filter, because the popup's tooltip is fixed while the label follows the filter; the fix is to select the tooltip from the current filter. (5, suggestion, maintainability) two parameters configure the same hidden store, inviting a caller to inject the wrong one; the fix is to keep one named parameter. (6, suggestion, correctness) a failed local hide leaves the row unchanged with no feedback and the failure flag is never shown; the fix is to check the returned value and to surface the failure. Its non-issues: the version bypass in the source is safe because the client still refuses anything but 2.0.22; the child count read without a version gate is safe because the read is read-only and the menu still gates the delete entry; and an uncertain result is reconciled by the view, fork, rename and delete feed signal and the behind flag.
