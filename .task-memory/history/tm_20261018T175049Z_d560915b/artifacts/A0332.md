Resolved Decisions\n\nOne coherent technical direction, no open option menu.\n\n- D1 — **Child identity comes from the native subagent tool's metadata.** The adapter edge reads `metadata.sessionID` from the tool's terminal frame (`session.tool.success` / `session.tool.failed`) and from the history tool block's `state.metadata.sessionID`, and publishes it as the canonical `ToolCall.child`. The `<task id>` envelope is discarded as unproven; no envelope parsing, no regex over assistant text, no title/time correlation. A malformed or absent `metadata.sessionID` leaves `child` null and never fails the frame.\n- D2 — **The card is classified canonically.** The harness maps the native tool name `subagent` to the already-existing `ToolKind.subagent` (both `tool_projection.dart` and `history_projection.dart`); the feature layer never sees the native name. `ToolCall.child != null` means \"observed child identity\"; `kind.known == ToolKind.subagent` means \"this is a task/subagent card\".\n- D3 — **The child set is a first-class canonical read.** `packages/codewalk_core` gains `ChildSession{ref, createdAt}` and `ChildSessionSet{children, complete}` plus a pure resolver. `complete` is true only when the endpoint's page proves there is no further page; no count-based or heuristic completeness is ever used.\n- D4 — **`SessionSummary.createdAt` is added (nullable).** Populated from `time.created`; absent or unusable leaves it null (truthful unknown) and never fails the page. It exists only to order the child set by creation; the endpoint's `order=asc` is treated as a transport detail, not as the ordering proof.\n- D5 — **Resolution is a pure function in `codewalk_core`.** Order: observed → sole → Nth-by-creation → unresolved. The Nth rule requires a complete child set, `childCount == taskCardCount`, a known `createdAt` for every child, and an in-range ordinal. Every other case is unresolved (open nothing + localized notice).\n- D6 — **The child view reuses the ordinary session route.** The card pushes `/s/<host>/<childNativeId>?sub=1`. `?sub=1` means \"opened as a sub-conversation\": no persisted workspace tab, and the warm live view is released when the route is popped. *Child-ness* (read-only selection chip, parent-return control) is derived from the authoritative `summary.info.lineage.parent`, never from the route flag, so a stale or forged flag can never redirect to a wrong parent.\n- D7 — **Return to the parent** uses `context.go('/s/<host>/<parentNativeId>')`; the parent's warm `SessionLiveController` owns the viewport (`SessionLiveScroll`), so the parent's warm viewport is preserved whenever that view is retained. The pushed route additionally gives system back the parent walk for free.\n- D8 — **Progress frames stay non-projecting.** `session.tool.progress` keeps returning null (the documented \"three recognized phases return null\" contract). Projecting it would put a non-durable resident in the tool chain and make the next durable frame raise `ResyncRequired`. Consequently the observed identity appears at the tool's terminal durable frame or in history; a still-running card resolves only through the server-side child set.\n- D9 — **The unresolved notice is a `SnackBar`** (non-blocking, localized, one action-free message per resolution).\n- D10 — **Four new l10n keys** across all 14 locales, reusing the existing `livePermissionChildBadge` for the card badge: `childConversationOpen`, `childConversationUnresolved`, `childConversationAmbiguous`, `childConversationReturnToParent`.\n\n6.
