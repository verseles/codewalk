# Unified Research Report

## Request and Research Scope
GLOBAL: establish Flutter3.44.1 testWidgets timer-invariant ordering relative to addTearDown. Technical research in English, using official Flutter sources; no local-project facts researched.

## Complete Findings
The exact3.44.1 binding source runs the test callback, unmounts remaining widgets, pumps and then calls _verifyInvariants inside _runTestBody. AutomatedTestWidgetsFlutterBinding checks pending periodic and non-periodic timers there. The same version's testWidgets registers binding.postTest through addTearDown but returns binding.runTest, so package-level teardown callbacks run after this invariant check. A timer owned outside the widget tree must therefore be canceled/disposed before the callback returns, preferably through its actual owner or a try/finally inside the callback. Merely registering disposal in addTearDown is too late for this pin. Sources: https://raw.githubusercontent.com/flutter/flutter/3.44.1/packages/flutter_test/lib/src/binding.dart and https://raw.githubusercontent.com/flutter/flutter/3.44.1/packages/flutter_test/lib/src/widget_tester.dart .
Official issue144472 reproduces this exact timer/addTearDown ordering, and issue123189 distinguishes cleanup checked within testWidgets from later package teardown. https://github.com/flutter/flutter/issues/144472 and https://github.com/flutter/flutter/issues/123189 .
