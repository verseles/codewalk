## Candidate findings identified (not yet finalized into YAML)

1. **Warning / correctness** — `lib/app/workspace_chrome_controller.dart:104-109`: `syncEscalated` (10 s of an unresolved reconnect) returns `WorkspaceBadgeKind.serverAlert`, rendered red with "server needs attention" (`workspace_chrome.dart:59-68`), even when endpoint health is healthy. This contradicts the class's own doc invariant ("Health never borrows the stream's reconnecting state to claim an endpoint is offline") and the v1 rule that a sync/reconnect state must not override a healthy active-server summary.
2. **Warning / edge case** — `workspace_chrome_controller.dart:213-241` + `:92-93`: `_graceEnd` derives from `health.resumedAt`; when `resumedAt` is null (app started while backgrounded, health `start(foreground: false)`), `_graceEnd` = `now + 5 s` on every evaluation, so `!now.isBefore(_graceEnd)` is never true and the `serverAlert` badge can never be produced.
3. **Warning / edge case** — `workspace_chrome_controller.dart:104-109` vs `:150-152`: between the 5 s grace expiry and the 10 s escalation there is a window where a still-reconnecting session produces no badge at all, then abruptly a red server badge — an inconsistent state machine.
4. **Suggestion / maintainability** — `endpoint_health_controller.dart:87-92, 121-134` vs `:214-233`: `view()` recomputes credential failure from the live credential while `_canProbe`/`_sync` use the captured `record.credential`; `_matches` does cover expiry, but the two sources of truth can disagree briefly after a credential repair.
