# Plano #471 — helperGrok-47-high (delivered)

## Direção
- Sem Dio (regra de arquitetura); novo cliente `dart:io` em `lib/platform/releases/` com redirects manuais.
- Allowlist de hosts vazia até observar os `Location` reais (etapa 1 bloqueia o fetcher; não adivinhar).
- Integridade: SHA256SUMS + `release-manifest.json` — tag, sha256, size, version_code, abi arm64-v8a, application id e signer_sha256 contra o digest publicado.
- Downgrade: se `version_code <= buildNumber`, não baixa.

## Arquitetura
- `UpdateCheckController` segue check-only; novo `ApkUpdateController` app-scoped só em androidArm64.
- Ports injetados: `ApkAssetFetcher`, `ApkIntegrity` (puro), `ApkInstaller` (open_filex), `InstallPermission` (MethodChannel), `ApkFileStore`, `Clock`.
- Estados: idle, downloading, verifying, needsPermission, installing, handedOff, failed.
- `open_filex` 4.7.0 usa FileProvider próprio `${applicationId}.fileProvider.com.crazecoder.openfile`; `getTemporaryDirectory()` serve. Não retargetar o FileProvider do app.
- Canal `com.verseles.codewalk/v2-apk-install`: `canRequestPackageInstalls` e `openUnknownSourcesSettings`.
- `<queries>` no manifest para ACTION_VIEW + mime APK (API 30+).

## Comportamento
- Sem browser; progresso 1%/100ms; cancel/retry; handedOff ≠ instalado.
- Beta opt-in default stable; guardas V2-077A intactas; Linux inalterado.
- Sem foreground service; morte do processo limpa no próximo launch.

## Diferenciais
- Verificação de manifest + downgrade + assinante publicado (mais rigoroso que SHA256SUMS sozinho).
- Exige observação real dos hosts de redirect antes de shipar o fetcher.
- Canal nativo para unknown sources e `<queries>`.

## Riscos/limites
- Allowlist vazia bloqueia download real até a observação.
- SHA256SUMS/manifest compartilham o domínio de confiança da release.
- Sem resume/background service; sem detecção de cancelamento do instalador.
