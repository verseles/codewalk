## 1. Transport fundamentals

### 1.1 Process modes, bind address, ports

`opencode serve [--hostname H] [--port P] [--cors ORIGIN]… [--service | --stdio]` — "Start the v2 API and web server" (V2 `packages/cli/src/commands/commands.ts#L537-L551`; handler `packages/cli/src/commands/handlers/serve.ts`; process `packages/cli/src/server-process.ts`).

| Mode | How | Hostname | Port | Password | Output |
|---|---|---|---|---|---|
| foreground (`default`) | `opencode serve` | `--hostname` or `127.0.0.1` | `--port`, else **4096, then 4097, 4098…** on `EADDRINUSE` (V2 `packages/server/src/process.ts#L139-L149`) | `OPENCODE_PASSWORD` (or legacy `OPENCODE_SERVER_PASSWORD`) else **random 32-byte base64url** | stdout: `server listening on http://H:P` and, if the password was generated, `server password <pw>` (V2 `packages/cli/src/server-process.ts#L78-L84`, `#L161-L164`) |
| `--stdio` | lifetime bound to stdin (exits when stdin closes) | same | same | same; the password env vars are then removed from the server's own environment so spawned tools do not inherit them | stdout one JSON line `{"url":"http://…"}` (V2 `packages/cli/src/server-process.ts#L163`) |
| `--service` (managed background service) | `opencode service start` spawns `opencode serve --service` | service config `hostname` or `127.0.0.1` | service config `port` or **`0xc0de` = 49374** for channels latest/dev/beta/next (`0xc0df`=49375 for `local`, hash-derived otherwise) (V2 `packages/cli/src/services/service-config.ts#L35-L39`) | service config `password`, generated once and persisted | writes registration file (§E.4); process `chdir`s to the user HOME (V2 `packages/cli/src/server-process.ts#L55`) |

The server **refuses to start without a password** (`Missing server password`, V2 `packages/server/src/process.ts#L52`). There is no unauthenticated mode in v2 (v1 allowed it).

The same port also serves the **web app** (`packages/cli/src/services/web-ui.ts`): any path that is not `/api`, `/api/*`, `/auth/*` or `/openapi.json` returns static assets or `index.html` **without authentication** (V2 `packages/cli/src/services/web-ui.ts#L16-L27`). Consequence: v1 paths such as `/global/health`, `/session`, `/event` return **HTTP 200 `text/html`** on a v2 server — never use them for detection; probe `GET /api/info` (v2) vs `GET /global/health` returning JSON (v1).

Readiness: while the app layer boots, every request except authenticated `GET /api/info` gets `503 {"code":"service_starting"}` + `retry-after: 1`; failed boot → `503 {"code":"service_failed","message":…,"action":"Run \`opencode service restart\` …"}`; shutting down → `503 {"code":"service_stopping"}` (V2 `packages/server/src/process.ts#L172-L231`). Note: these bodies are **not** the `_tag` error envelope.

### 1.2 Authentication

Source: V2 `packages/server/src/auth.ts`, `packages/server/src/middleware/authorization.ts`.

- **HTTP Basic**, username is fixed **`opencode`** (`username: "opencode"`, V2 `packages/server/src/auth.ts#L20`; v1's `OPENCODE_SERVER_USERNAME` no longer exists). Header `Authorization: Basic base64("opencode:<password>")`.
- Alternative for clients that cannot set headers (WebSocket, EventSource, `<img>`): query **`?auth_token=<base64("opencode:<password>")>`** (V2 `packages/server/src/middleware/authorization.ts#L11`, `#L31-L39`).
- **Pairing tokens** (new in v2): `POST /api/pair` (authenticated) → `{code, expires_in: 300}`; the user opens/scans `http(s)://<server>/auth/connect/<code>` (printed + QR by `opencode pair`, V2 `packages/cli/src/commands/handlers/pair.ts#L12-L60`). `GET /auth/connect/{code}` needs **no auth**; code is single-use, 5-min TTL (V2 `packages/server/src/pairing.ts#L7`). If the request `Accept` header does not contain `text/html` the response is JSON **`{"token":"<expiresEpochSec>.<hmac>"}`**; that token is accepted **anywhere the password is** (use it as the Basic password with user `opencode`), valid **30 days**, HMAC-SHA256 keyed by the server password (rotating the password revokes all tokens) (V2 `packages/server/src/auth.ts#L16`, `#L32-L62`). Browsers (Accept contains `text/html`) instead get a redirect to `/` + `HttpOnly` cookie `opencode_session_<port>` (same-origin only). Expired/used code → `401` JSON `UnauthorizedError` (or text for browsers). **This is the recommended way to onboard a mobile app** (scan QR → redeem → store token).
- `401` body: `{"_tag":"UnauthorizedError","message":"Authentication required"}`. The `www-authenticate: Basic realm="Secure Area"` challenge is only added when the request has no `sec-fetch-mode` header or it is `navigate` (V2 `packages/server/src/middleware/authorization.ts#L42-L55`).
- PTY WebSockets may alternatively use a single-use **ticket** (§A12).
- Password sources for clients: env `OPENCODE_PASSWORD` given to the server, the `server password …` stdout line, `opencode service get password`, or `password` in the service registration file (§E.4).

### 1.3 CORS

Allowed origins: none (non-browser), `http://localhost:*`, `http://127.0.0.1:*`, `oc://renderer`, `tauri://localhost`, `http(s)://tauri.localhost`, `https://*.opencode.ai`, plus each `--cors` value / service `cors` (V2 `packages/server/src/cors.ts#L11-L21`). Native mobile HTTP clients are unaffected.

### 1.4 Location (directory) scoping

v2 replaces v1's `?directory=` / `?workspace=` with a **location**:
- Query **`location[directory]=<absolute path>`** (deepObject style), or header **`x-opencode-directory: <URI-encoded absolute path>`**; fallback = **server process cwd** (HOME for the service) (V2 `packages/server/src/location.ts#L39-L48`). `workspace` / `x-opencode-workspace` are gone from the HTTP contract (V2 `V2_HTTP_API_AUDIT.md`, "Resolved during audit").
- Scope column in the index: **L** = location-scoped (send the directory), **S** = session-scoped (location derived from the session; no directory needed), **G** = global.
- Location-scoped responses are wrapped: **`{ location: { directory }, data: … }`** (`Location.response`, V2 `packages/schema/src/location.ts#L34-L36`). Session-group responses use `{ data: … }` (no location) or no body.
- `POST /api/session` takes the directory **only from its JSON body** (`location.directory`) — header/query are ignored there.

### 1.5 Wire conventions

- JSON everywhere except `fs.read` (raw bytes), `experimental.fs.write` (raw request body), SSE endpoints and WebSockets.
- Timestamps are **epoch milliseconds** numbers (`DateTimeUtcFromMillis`, V2 `packages/schema/src/schema.ts#L25-L30`).
- Optional fields are encoded as absent keys; requests may also send `null` for optional fields (OpenAPI renders them `X | null`; the server's `optional` helper decodes both, V2 `packages/schema/src/schema.ts#L12-L18`).
- Error envelope = Effect `TaggedError`: `{"_tag":"<Name>","message":"…", …extra}`, status from the error class (V2 `packages/protocol/src/errors.ts`):

| Status | `_tag` (extra fields) |
|---|---|
| 400 | `InvalidRequestError {kind?, field?}`, `InvalidCursorError`, `FormInvalidAnswerError {id}`, `RpcError {type, data?}`, `InstructionEntryValueTooLargeError` |
| 401 | `UnauthorizedError` |
| 403 | `ForbiddenError` |
| 404 | `SessionNotFoundError {sessionID}`, `MessageNotFoundError {sessionID, messageID}`, `PermissionNotFoundError {requestID}`, `FormNotFoundError {id}`, `AgentNotFoundError`, `ProviderNotFoundError`, `IntegrationNotFoundError`, `IntegrationAttemptNotFoundError`, `IntegrationMethodNotFoundError`, `ProjectNotFoundError`, `FileNotFoundError {path}`, `SkillNotFoundError`, `McpServerNotFoundError`, `CommandNotFoundError`, `PtyNotFoundError`, `ShellNotFoundError` |
| 409 | `ConflictError {resource?}`, `SessionBusyError {sessionID}`, `FormAlreadySettledError {id}` |
| 500 | `UnknownError {ref?}`, `CommandExecutionError`, `RpcInternalError` |
| 503 | `ServiceUnavailableError {service?}` |

- **IDs** (V2 `packages/schema/src/identifier.ts#L14-L30`): 12 hex chars of `(ms_timestamp*4096+counter)` + 14 base62 random chars, with prefix: `ses_` (session; **descending** = bitwise-NOT timestamp so newer sort first), `msg_` (messages/inbox items; ascending), `evt_` (events), `per_` (permission requests), `frm_` (forms), `psv_` (saved permissions), `pty_`, `sh_` (shell jobs), `cred_`. Clients may mint `ses_`/`msg_`/`frm_` IDs (create/prompt/shell/compact accept `id`) for optimistic UI and idempotent retries. Projected messages derived from an event use `msg_` + the event id suffix (`SessionMessage.ID.fromEvent`, V2 `packages/schema/src/session-message.ts#L23-L30`).
- **Pagination**: opaque `cursor.next` / `cursor.previous` strings (base64url JSON). Sessions default 50; messages default 50 (max 200), default order `desc`.

## D. Quotas, usage, rate limits — what is (and is not) exposed

**There is no quota / balance / subscription-usage endpoint in the v2 HTTP API.** Search of `packages/{protocol,server,core,schema}` for `quota|balance|usage limit|ratelimit|credits` finds only error classification and accounting. What a client CAN get:

1. **Per-session totals**: `Session.Info.cost: number` (USD) + `tokens: {input, output, reasoning, cache:{read, write}}` (V2 `packages/schema/src/session.ts#L31-L56`), live-updated by the ephemeral SSE event `session.usage.updated {sessionID, cost, tokens}`. Totals include title-generation and compaction usage (recorded via the internal durable `session.usage.recorded`, which is never sent to clients — V2 `packages/schema/src/session-event.ts#L158-L167`, `#L708-L713`).
2. **Per assistant step**: `session.step.ended {cost, tokens, finish, rawFinish?}` / `session.step.failed {cost?, tokens?}`; projected onto `Session.Message.Assistant.cost/tokens/finish`. `TokenUsage.total = input+output+reasoning+cache.read+cache.write` (V2 `packages/schema/src/token-usage.ts#L6-L20`). Cost is computed server-side from `Model.Info.cost` (`SessionUsage.calculateCost`, V2 `packages/core/src/session/runner/step.ts#L236-L238`).
3. **Aggregates**: `GET /api/experimental/session/stats?from=&to=&project=&timezone=&tools=none|summary|detail` → `SessionStats.Info {range, sessions, subagents, prompts, steps, tokens, cost, tools, activeDays, streak, activity[{date, steps}], models[{model, steps, tokens, cost}]}` (V2 `packages/schema/src/session-stats.ts#L51-L68`).
4. **Model limits & prices**: `GET /api/model` → `Model.Info.limit {context, input?, output}` and `cost: [{tier?: {type:"context", size}, input, output, cache:{read, write}}]` in **USD per 1M tokens** (`Money.USDPerMillionTokens`), `status`, `capabilities {tools, input[], output[]}`, `variants[]`. (Rendered in file 12 §10.)
5. **Rate limits**: provider headers `retry-after`, `retry-after-ms`, `x-ratelimit-{limit,remaining,reset}-*`, `anthropic-ratelimit-*-{limit,remaining,reset}` are parsed into `HttpRateLimitDetails` inside `packages/ai` (V2 `packages/ai/src/route/executor.ts#L23-L78`) but **are not forwarded to clients**: the client-facing error is only `Session.StructuredError {type, message, status?, response?: {body}}` (V2 `packages/core/src/session/to-session-error.ts#L28-L96`). Retry visibility: durable `session.retry.scheduled {assistantMessageID, attempt, at /* epoch ms when the next attempt fires */, error}` (V2 `packages/core/src/session/runner/retry.ts#L86-L105`). Policy: exponential 2 s → capped 10 s per gap, max 10 retries, jittered; a provider `retry-after` raises the delay up to 15 min (V2 `packages/core/src/session/runner/retry.ts#L31-L57`). Retryable = `RateLimit`, `ProviderInternal`, some `Transport`, incomplete streams, unknown; `x-should-retry` header overrides (V2 `packages/ai/src/provider-error.ts#L69-L95`).
6. **Error `type` strings relevant to quotas** (V2 `packages/core/src/session/to-session-error.ts#L28-L58`): `provider.rate-limit` (retried), `provider.quota` (NOT retried; includes OpenCode Zen account caps: codes `insufficient_quota`, `usage_not_included`, `billing_error`, `gousagelimiterror`, `freeusagelimiterror`, `creditlimitexceeded`, V2 `packages/ai/src/provider-error.ts#L107-L115`), `provider.auth`. ChatGPT-subscription ("token sharing") errors are rewritten to fixed messages, e.g. `"ChatGPT usage limit reached. Check ChatGPT Settings → Usage for details."` (V2 `packages/core/src/session/to-session-error.ts#L10-L26`).
7. **OpenCode Zen / Go limits**: the Zen gateway answers `429` with body `{"type":"error","error":{"type":"GoUsageLimitError"|"FreeUsageLimitError"|"RateLimitError"|"BlackUsageLimitError","message":…},"metadata":{"workspace":…,"limitName":"weekly"|"monthly"|"5 hour"}}` + `retry-after` (V2 `packages/console/app/src/routes/zen/util/handler.ts#L505-L530`, `#L900-L960`). In v2 this reaches the client only as `error.response.body` of a `provider.quota` failure (**inferred** from the classification chain above). v1 instead converted it into `SessionStatus.retry.action {reason:"free_tier_limit"|"account_rate_limit", provider, title, message, label, link}` (V1 `packages/opencode/src/session/retry.ts#L85-L150`). The v2 schema still declares `session.status` with that `action`, and the v2 web app still listens for it (V2 `packages/app/src/session/usage-exceeded-dialogs.tsx#L84-L120`), but **no publisher of `session.status` exists in v2 core/server** (repo-wide search; **inferred dead path**). A CodeWalk "usage exceeded" UX must parse `response.body` of `session.step.failed`/`session.execution.failed`/`session.retry.scheduled` errors.
8. **No subscription usage meters** (Claude Pro/Max, ChatGPT plan, Copilot quota, Go balance) are fetched or exposed by the v2 server.

### E.2 Install script behaviour (v2)

- Options: `-v|--version <ver>` (or env `VERSION`), `-b|--binary <path>`, `--no-modify-path`. Install dir fixed **`$HOME/.opencode/bin`** (V2 `install#L69`) — **the same path v1 uses**, so installing v2 replaces the v1 `opencode` binary.
- Latest version from `https://opencode.ai/update/api/latest/cli/npm`; download `https://registry.npmjs.org/@opencode/cli-<target>/-/cli-<target>-<ver>.tgz`, extract `package/bin/opencode` (V2 `install#L169-L207`, `#L327-L345`); falls back to the legacy scope `@opencode-ai/cli-<target>` for old explicit versions.
- Installs a legacy shim `opencode2` → `opencode` (V2 `install#L358-L382`), then adds the dir to PATH in shell rc files unless `--no-modify-path`.

### E.3 Self-upgrade

`opencode upgrade|update [target] [--method curl|npm|pnpm|bun|yarn|vp|brew]` (V2 `packages/cli/src/commands/commands.ts#L60-L74`, methods V2 `packages/cli/src/services/updater.ts#L13`). Method detection: binary at `~/.opencode/bin/opencode` → `curl` (re-runs `https://opencode.ai/v2/install`); Homebrew Cellar `opencode-beta|opencode-v2` → `brew`; else probes `npm/pnpm/bun/yarn/vp list -g` for `@opencode/cli` (V2 `packages/cli/src/services/updater.ts#L170-L212`). Policy from global config `update: "disable"|"notify"|"auto"` (legacy `autoupdate`), default `notify`. The running service publishes SSE `installation.update-available {version}` / `installation.updated {version}` (V2 `packages/server/src/process.ts#L112-L118`). **There is no HTTP upgrade endpoint** (v1 had `POST /global/upgrade`). `opencode uninstall [--keep-config] [--keep-data] [--dry-run] [--force]` exists.

### E.4 Headless launch / discovery for a third-party app

Recommended patterns (all source-verified unless noted):
1. **Own child process**: spawn `opencode serve --stdio [--hostname 0.0.0.0] [--port N]` with env `OPENCODE_PASSWORD=<generated>`; read the first stdout line `{"url":"http://…"}`; the server exits when the parent closes stdin (V2 `packages/cli/src/server-process.ts#L161-L170`, `#L197-L213`).
2. **Plain foreground**: `opencode serve --port 4096`; parse `server listening on <url>` and `server password <pw>` (only printed when no env password).
3. **Managed background service** (what the v2 TUI/desktop use): `opencode service start|stop|restart|status`, `opencode service get|set|unset <disabled|hostname|port|password|cors|env> …` (V2 `packages/cli/src/commands/commands.ts#L471-L512`). Config file `$XDG_CONFIG_HOME/opencode/service.json` = `{disabled?, hostname?, port?, password?, cors?, env?}` (mode 0600, V2 `packages/cli/src/services/service-config.ts#L14-L21`). Registration file **`$XDG_STATE_HOME/opencode/service.json`** (default `~/.local/state/opencode/service.json`, channel-suffixed for non-standard channels) = `{ id, version, url, pid, password }` written by the running service and removed on exit (V2 `packages/cli/src/services/service-registration.ts#L23-L30`, type V2 `packages/client/src/service.ts#L46-L57`). To expose it to phones: `opencode service set hostname 0.0.0.0` then `opencode pair` (prints `http://<lan-ip>:49374/auth/connect/<code>` + QR).
4. Paths (XDG, V2 `packages/util/src/global-roots.ts#L4-L20`): data `~/.local/share/opencode` (DB `opencode.db`, overridable `OPENCODE_DB`, channel-suffixed DB for non-standard channels — V2 `packages/cli/src/database-path.ts#L4-L13`), config `~/.config/opencode`, state `~/.local/state/opencode`, cache `~/.cache/opencode`, tmp `$TMPDIR/opencode`. v2 migrates v1 history from the same data dir on first start (`GET /api/experimental/migration/v1`).
5. Server-affecting env vars read by `serve` (V2 `packages/cli/src/server-process.ts#L59-L120`, `packages/cli/src/env.ts`): `OPENCODE_PASSWORD` / `OPENCODE_SERVER_PASSWORD`, `OPENCODE_CONFIG_DIR`, `OPENCODE_CONFIG`, `OPENCODE_CONFIG_CONTENT`, `OPENCODE_CONFIG_PROJECT_DISABLE` / `OPENCODE_DISABLE_PROJECT_CONFIG`, `OPENCODE_MODELS_URL`, `OPENCODE_MODELS_PATH`, `OPENCODE_DISABLE_MODELS_FETCH`, `OPENCODE_FILEWATCHER_DISABLE` / `OPENCODE_DISABLE_FILEWATCHER`, `OPENCODE_DISABLE_FFF`, `OPENCODE_GIT_BASH_PATH` (Windows), `OPENCODE_CLIENT` (app name reported to MCP), `OPENCODE_DB`, `OPENCODE_DISABLE_CHANNEL_DB`, `OPENCODE_SIMULATE`, `OPENCODE_DISABLE_AUTOUPDATE`, XDG_*.
6. Version check from the client: `GET /api/info` → `{version}` (e.g. `"2.0.21"`; source builds report `local`). Compare with the update API for "update available" UX.
7. ARM64 Linux hosts (CodeWalk's cloud machines) are first-class targets (`linux-arm64`, `linux-arm64-musl`).
