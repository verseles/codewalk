> 📣 CodeWalk 2.4.0 makes Markdown links clickable across chats, notices, and subagent reports, renders background shell completion results cleanly instead of raw XML, and aligns OpenCode event handling with the official v2.3+ Web client.

### Clickable Markdown links

- Tapping Markdown links and bare URLs (`http`, `https`, `//`, `www.`, `mailto:`) inside live and read-only history timelines — including assistant and user messages, expanded reasoning, light notices, and subagent replies — now opens them externally in the browser or default handler.
- Validates link schemes before launch so unsafe or relative links (`javascript:`, `file:`, `data:`, local paths) never execute and show a localized **Unable to open link** message.
- Moves the collapse tap target of expanded rich light notices onto the leading icon so tapping links or selecting text inside an expanded note works without collapsing it.

### Background shell results & shell status handling

- Parses background shell completion messages (`<shell ...>` and OpenCode 2.3+ `<background-result kind="shell" ...>`) into compact single-line shell rows with command text, exit/timeout/killed/interrupted badges, and full credential-redacted output in the details dialog.
- Folds background shell reports into activity stretches as commands, enriches matching background shell entries in the robot capsule with their terminal outcome and output, and suppresses duplicate echoes of user `!` shell runs.
- Strips host `PID:` and capture-file lines from background/interrupted shell output, projects `Command cancelled` / interrupted shell failures as interrupted, and supports `killed` / `signal` facts plus legacy `bash`, `apply_patch`, and `task` tool names.

### Official OpenCode Web client event parity

- Handles OpenCode 2.3+ stream and history events cleanly: `session.step.first-token`, `session.skill.activated` (quiet skill note), `session.moved` (live directory update, move notice, and automatic model/agent catalog refresh), `session.archived` / `session.unarchived`, `worktree.updated` / `worktree.resolved`, and `idle` direct error cards.
- Refreshes location model/agent catalogs on `integration.updated`, `config.updated`, `credential.updated`, and `credential.switched` events, and triggers a bounded state repair if execution finishes while a tool call is still open in streaming/pending state.
- Unwraps `<background-result>` (subagent and other background jobs), `<system-update>`, and `<fork-notice>` envelopes cleanly and maps OpenCode 2.3+ provider limit errors (`free-limit`, `go-limit`, `budget-limit`, `model-budget-limit`) to quota error cards.
