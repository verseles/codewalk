> 📣 CodeWalk 2.6.0 hardens large and long-lived OpenCode v2 sessions with adaptive history paging, bounded tool results and error messages, automatic repair budget recovery, and smooth viewport backfill.

### Large & long-lived session resilience

- Lowers live hydration and older-history paging to 20 native messages per page and automatically halves the requested page size down to 1 whenever a response exceeds the HTTP body limit or projection budget, preventing large conversations from degrading with a false "could not keep session up to date" banner.
- Adds a bounded post-layout timeline backfill probe (up to 9 additional older pages while following a short viewport) so conversations with compact or folded rows fill the screen smoothly without losing follow mode or marking jump-to-latest.
- Preserves resident older history, pagination cursors, and untrimmed window state across overlapping tail re-hydrations, and replaces stale disjoint windows cleanly when reconnecting after many new messages.
- Isolates routine child-session and manual refreshes from the per-generation error-repair strike counter, resets the repair budget after a 30-second healthy cooldown or a clean settled turn, skips validated pre-hydration no-op streaming tool-input frames, and clears any sticky degraded status once a live snapshot arrives.

### Bounded tool inputs, outputs, and error messages

- Replaces atomic rejection of oversized tool inputs, outputs (>64 KiB JSON-escaped, 4,096 nodes, or 128 output parts), and tool/compaction error messages (>8 KiB) with bounded, redacted prefixes that keep primary target keys (`command`, `path`, `filePath`, `pattern`, `url`, `query`, `name`, `header`) first and redact credentials against the full source text before cutting.
- Labels client-shortened tool outputs and error messages clearly inside the tool details dialog across all 14 locales while keeping single-message budget overflow and malformed payloads fail-closed.
